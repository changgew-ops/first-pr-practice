# 게임 기획서 (초안 v0.1)

한국프로농구(KBL) 구단 GM 시뮬레이션 + 카드 수집·육성. 웹 / 싱글 플레이.

> 상태: 초안. 아래 수치와 이름은 모두 **제안값(예시)** 이며 플레이 테스트로 조정한다.
> 이 문서는 사람과 AI 에이전트 모두의 기준 문서다. 규칙을 바꾸면 코드보다 먼저 이 문서를 고친다.

## 1. 한 줄 요약

KBL 10개 구단 중 하나를 맡아 선수 카드를 모으고 키우며, 이적 시장과 라인업을 운영해 시즌을 치르는 싱글 플레이 웹 게임.

## 2. 설계 기둥

1. **육성이 중심, 수집이 동기**: 새 선수를 얻는 재미와 한 선수를 키우는 재미가 서로를 받쳐준다.
2. **직접 조작 경기 없음**: 라인업과 전술을 정하면 시뮬레이션이 결과를 계산한다. 선택의 결과가 숫자로 설명되어야 한다.
3. **작게 시작**: MVP는 1시즌, 저장 기능, 단순한 이적까지만. 에셋과 기능은 그다음에 늘린다.

## 3. 코어 루프

```
선수 획득(드래프트/FA/트레이드) → 훈련·육성 → 라인업 편성 → 경기 시뮬레이션
        ↑                                                      ↓
   다음 시즌 ← 계약·재정 정산 ← 시즌 보상·성장 ←←←←←←←←←←←←←←←←┘
```

한 번의 "턴" = 하루 일정(훈련 또는 경기). 한 시즌 = 정규리그 54경기(10개 구단 6라운드) + 시즌 종료 정산·이적 시장. 54경기는 일괄 시뮬레이션으로 빠르게 넘길 수 있게 한다.

**실명 사용 원칙**
- 구단 이름과 연고지는 실제 것을 쓴다. 구단 로고와 공식 엠블럼은 쓰지 않는다(팀 컬러와 텍스트 이름만).
- **선수 이름은 실명을 쓸 수 있다.** 단, 개인·지인 소규모 플레이(비상업)용이다. 능력치·잠재력·계약은 실제 수치가 아니라 이름을 시드로 한 **가상 값**이다.
- 기본 데이터는 전원 가상 선수이고, 실명은 `data/rosters/<구단id>.csv`로 넣으면 반영된다(`data/rosters/README.md` 참고). 실제 로스터는 공식 자료로 사람이 확인해서 채운다. 에이전트가 검색 결과로 추측해 채우지 않는다.
- **선수 이미지는 실제 사진을 가져와 쓰지 않는다.** 사진은 촬영자·KBL·구단의 저작물이다. 이미지는 직접 가진 파일을 `assets/portraits/<선수id>.png`에 넣거나, 실존 인물과 닮지 않은 스타일화된 카드 일러스트를 쓴다.
- 링크를 불특정 다수에게 공개하거나 수익 요소를 넣게 되면 KBL·구단·선수 측 이용 허락을 별도로 확인한다.

### 4.2 규정 (2026-27시즌, 공식 원문 대조 완료. 원문은 `docs/KBL_RULES_SOURCE.md`)

| 항목 | 내용 |
|---|---|

| 외국 선수 샐러리캡 | 100만 달러 (1인 상한 70만 달러) |
| 외국 선수 | 구단당 2명 보유, 2명 출전. 2·3쿼터는 2명 동시 출전 가능, 1·4쿼터는 1명만 출전 |
| 정규리그 | 10개 구단, 54경기 |
| FA | 시즌 종료 후 협상 시작. FA로 타 구단 이적 시 연내 이적 제한 규정은 폐지됨 |
| 드래프트 | 신인 드래프트 + 해외 3년 이상 경력 선수 특별 드래프트(구단이 같은 확률로 지명) |
| 소프트캡 | 캡을 넘겨도 되지만 초과분의 30%(10% 이하) / 40%(10~20%) / 50%(20% 초과)를 기금으로 낸다 (2021-22 도입, 보수 규정 제4조로 확인) |
| FA 보상 | 자유계약선수 관리 규정 제6조(2027-28시즌부터): 전년도 보수 서열 30위 이내는 "보상선수 1명 + 전 시즌 보수의 25%" 또는 "보수의 100%" 중 선택, 31~40위는 보수의 50%, 40위 밖은 보상 없음. 보호선수 4명 |
| 트레이드 | 세부 규정을 확인하지 못함. 아래 5.4의 게임용 단순 규칙을 사용 |
| 아시아쿼터 | 2025-26부터 도입, 연봉 상한 16만 달러, 국내 선수 샐러리캡에서 제외. **아직 게임에 없음** |

게임에서는 이 규정을 **설정 파일 하나**(`league-rules.json`)에 모아, 규정이 바뀌어도 코드 수정 없이 반영한다.

**규정 대조** (사용자가 붙여넣은 원문 `docs/KBL_RULES_SOURCE.md` 기준)

반영함:
- 최저 연봉 4,200만원(보수 규정 제9조): `salaryCap.minSalaryEok` 0.42. 소프트캡 면제 계약선과 긴급 영입 연봉도 이 값으로 맞췄다.
- 신인 보수(규약 제98조): 1라운드 1~4순위 0.8~1.2억, 5~10순위 0.5~0.8억, 2라운드 0.42~0.5억. 구간 안은 순번에 따라 선형으로 내려가는 게임용 보간(`rookieSalary`). 신인 계약기간은 1라운드 3년, 2라운드 2년(공식 범위 3~5년, 1~3년 안의 게임용 값).
- FA 보상(관리 규정 제6조): 위 표대로. 이전 값(2020년 정비 기준, 30위 이내 200%, 31~40위 100%, 41~50위 50%, 보호선수 5명)은 틀렸다.
- FA 계약기간(관리 규정 제4조): 30위 이내 3~5년(만 32세 이상 예외), 그 밖에는 5년 이하.
- 드래프트: 순번 추첨(공 40·40·40·40·14·14·6·6·0·0), 4라운드 뱀 순서, 3라운드부터 지명 포기(5.9).
- 소프트캡 납부 비율 30/40/50%: 이미 같았다.

반영하지 않음(게임에 대응하는 기능이 없거나 이후 과제):
- 인센티브: 보수의 30% 이내, 샐러리캡 10% 이상 계약은 20~30% 의무(보수 규정 제3조). 게임은 연봉만 쓴다.
- FA 자격은 계약 기간 중 매 정규시즌 절반 이상 출전(관리 규정 제2조). 게임은 계약 만료면 모두 FA다. FA 협상 일정(자율협상 15일, 영입의향서 3일, 원소속구단 재협상 4일)도 5라운드로 단순화했다.
- FA 보상 선수는 영입 구단이 낸 보호선수 명단 4명 밖에서 원소속 구단이 지명한다. 게임에서는 단장이 고르거나 자동 규칙이 고른다. 보호선수는 가치 상위 4명으로 자동 계산한다(영입한 30위 이내 FA는 반드시 보호에 들어가야 한다는 조건은 따로 적용하지 않았다).
- 신인 선급금(첫 시즌 연봉 × 계약기간의 30% 이내), 신인 월 수당, 출전수당, 팀 인센티브 6천만원.
- 외국선수: 보유 2명(이미 같음), 일시교체·시즌대체(2주·8주 기준, 기타 사유 교체 2회), 월 보수 상한, 에이전트 수수료 10%. 시즌 중 외국선수 교체 기능이 생길 때 이 원문을 쓴다.
- 샐러리캡 한도 자체(30억)는 이 원문에 없다(이사회가 정한다).

### 4.3 팀 이력 (구현됨)

KBL 출범(1997)부터 2025-26까지 **30개 시즌**의 정규리그 순위표와 플레이오프 대진을 구단별 계보로 정리했다 (`data/history/`).

- **출처**: KBL 공식 사이트의 시즌별 순위·플레이오프 화면을 녹화한 영상에서 옮겼다. 사람이 눈으로 읽은 값이라 빌드 때 자동 검증한다
  (승 합계 = 패 합계, 승률 = 승/(승+패), 순위 순서, 6강→4강→결승 대진 정합성). 2001-02 이후는 홈·원정 기록의 합까지 승패와 맞는다(예외는 2024-25 사이트 표시값 3건).
- **구단 계보**: 현재 10개 구단이 1997년부터 어떤 이름으로 이어졌는지 정리했다. 예: 광주나산 → 광주 골드뱅크 → 여수 골드뱅크 → 여수 코리아텐더 → 부산KTF → 부산KT → 수원 KT, 인천대우증권 → 인천신세기 → 인천SK → 인천전자랜드 → 대구 한국가스공사, 대구동양 → 대구오리온스 → 고양오리온스 → 고양 캐롯 → 고양 소노.
- **플레이오프**: 2007-08부터만 화면에 있다(2019-20은 코로나로 조기 종료). 우승 18회의 분포: 울산 현대모비스 5, 부산 KCC 4, 안양 정관장 4, 서울 SK 2, 원주 DB·창원 LG·고양 소노 각 1.
- **통산(1997~2025-26)**: 승률 1위는 울산 현대모비스(.555), 이어서 원주 DB(.547), 창원 LG(.525), 서울 SK(.520), 부산 KCC(.517). 서울 삼성(.431)은 정규리그 1위가 한 번이고 우승은 없다.

**게임에서 쓸 곳(제안, 아직 연결 안 함)**
- 구단 정보 화면: 연혁, 이름 변천, 우승·결승 횟수, 역대 순위 그래프
- **구단 명성**: 최근 우승·성적에 가중치를 두어 FA 선수의 구단 선호, 관중 수입, 신인 지원자 수에 반영
- 라이벌 관계: 결승에서 자주 만난 구단 쌍(원주 DB-울산 현대모비스, 서울 SK-창원 LG 등)
- 시즌 카드: 팀 이력의 시즌별 성적을 "그 시즌 팀 보정"으로 사용

**한계**: 우승 기록이 없는 시즌은 1997~2006-07(순위표만 있음)과 2019-20이다. 구단 계보 연결은 데이터에서 이름 변천이 이어지는 것으로 확인했고 공식 연혁과 대조하지 않았다.

## 5. 핵심 시스템 (MVP)

### 5.1 선수

| 항목 | 설명 |
|---|---|
| 기본 정보 | 이름, 포지션(PG/SG/SF/PF/C), 나이, 등번호 |
| 능력치 | 슛, 패스, 수비, 리바운드, 운동능력, 체력 (각 0~99) |
| OVR | 포지션별 가중 평균으로 계산한 종합 점수 |
| 코스트 | OVR로 정해지는 카드 비용(1~20). 라인업 제한에 쓴다 (5.7 참고) |
| POT | 성장 상한. 육성 한계를 정한다 |
| 희귀도 | 일반 / 레어 / 에이스 / 레전드 (카드 프레임·성장 상한과 연결) |
| 구분 | 국내 / 외국 선수 (캡과 출전 규정이 다르다) |
| 계약 | 연봉(억 원), 남은 계약 기간 |
| 상태 | 컨디션, 부상 여부 |

### 5.2 육성 (구현됨)

두 갈래다. **훈련**은 내가 맡은 구단에서 직접 하는 일이고, **노화·성장**은 모든 선수에게 시즌이 끝날 때 자동으로 적용된다.

**훈련** (`src/training.mjs`)
- 선수마다 집중 능력치 하나를 정한다. 체크포인트(9경기마다)에 훈련이 8회씩 반영되고, 경험치가 임계값을 넘을 때마다 능력치가 +1 오른다.
- 속도 = 기본 × **나이 배율** × **잠재력 여유 배율**. 22세 이하는 1.4배, 30대 초반은 0.3배다. 잠재력(POT)과 현재 OVR의 차이가 클수록 빠르고, 한계에 가까우면 거의 오르지 않는다.
- 능력치가 높을수록 한 단계 오르는 데 더 많은 경험치가 든다. 훈련은 잠재력 상한(POT)을 올리지 않는다.
- 효과(같은 시드, 부산 KCC를 20년 훈련 관리): 상위 8명 평균 OVR +2.4, 정규리그 승률 +5%p.

**노화·성장** (`src/offseason.mjs`, 시즌 종료 시)
| 나이 | 변화 |
|---|---|
| 25세 이하 | 잠재력까지 남은 여지에 비례해 모든 능력치가 오른다 (23세 이상은 0.6배) |
| 26~28세 | 전성기. 능력치가 ±1 안에서 흔들린다 |
| 29~30세 | **신체 능력(운동능력·체력)만** 해마다 −1~2 |
| 31~32세 | 기술 능력치도 −0~1 |
| 33세 이상 | 신체 −1~4, 기술 −0~2 |
| 27세 이상 | 성장 가능성이 사라져 POT = 현재 OVR |

- 이전 게임(카드야구 매니지먼트)의 "젊으면 성장·나이 들면 노쇠" 구조를 가져오되, 농구에서는 신체 능력이 기술보다 먼저 떨어지도록 나눴다.

**육성 프로그램: D리그·해외 유학** (`src/devprogram.mjs`, `league-rules.json`의 `devProgram`, 화면은 훈련 > "육성 프로그램")

KBL의 실제 D리그·유학 제도 세부는 확인하지 못했다. 아래 수치는 모두 게임용 가정이다(공식 값 아님).

| 항목 | D리그(교육리그) | 해외 유학 |
|---|---|---|
| 대상 | 24세 이하 국내 선수, 두 프로그램 합쳐 동시에 2명 | 같음, 계약이 2년 이상 남은 선수(돌아온 해에 계약이 끝나는 선수는 못 감) |
| 시기 | 정규리그 중 언제든 파견·소환 | 시즌 시작 전(0일차)에만 파견·취소. 시즌이 끝나야 복귀 |
| 효과 | 훈련 경험치 ×1.3 (체크포인트마다) | 한 시즌 훈련 경험치 ×1.8을 복귀 때 한꺼번에. ±40% 편차, 12% 적응 실패(×0.3), 성공 시 35% 확률로 잠재력 +1~3 |
| 비용 | 연봉은 그대로, 시즌 0.2억(참가한 날수 비례) | 유학비 0.8억 + 연봉의 50%. 유학 중 연봉 전액은 지출에서 빠진다 |
| 명단 | 등록 명단(라인업·자동 편성·트레이드·캡 계산)에서 빠진다. 소환하면 돌아온다 | 같음 |

- 구현: 파견된 선수는 진행기(`beginSeason`)의 `players`에서 빠져 `away`에 있고, 그래서 라인업·트레이드 제안·캡·정원 계산이 따로 손대지 않아도 자동으로 제외된다. D리그는 체크포인트 훈련을 배수로 받고, 유학은 `finish()`에서 선수별로 시드가 고정된 난수(`dev:<시즌>:<선수 id>`)로 성장해 돌아온다. 이 난수는 시즌 난수열과 별개라 프로그램을 쓰지 않으면 기존 시즌 결과가 그대로다.
- 시즌 정산(`settleYear`)에서 유학 중 선수의 연봉은 빼고 프로그램 비용만 장부(`ledger[구단].program`)에 넣는다. 캡 초과 기금도 유학 선수를 뺀 연봉으로 센다.
- 세션 조작 기록: `{ day, type: 'program', playerId, program: 'dleague' | 'abroad' | null, stat }`. 저장 파일 형식은 그대로고, 이전 저장은 이 조작이 없을 뿐이다.
- AI 구단은 쓰지 않는다.
- **결과 보고서 모양**(뉴스 등이 읽는다): 시즌 결산 항목 `entry.devProgram` = `{ playerId, name, teamId, program: 'dleague' | 'abroad', stat, days, before: { ovr, potential }, after: { ovr, potential }, outcome: 'normal' | 'success' | 'struggle', costEok }[]`. 프로그램을 쓰지 않은 시즌에는 키 자체가 없다. 세션에서는 `session.lastProgramReport`로 읽는다.
- 한계: D리그 선수는 경기에 나오지 않으므로 시즌 중 경기 기록에 따른 능력치 갱신을 받지 않는다. 연봉 기준 캡 계산에서는 빠지지만 시즌 정산에서는 D리그 선수의 연봉 전액을 낸다.

### 5.3 수집

- 시즌 종료 후 **신인 드래프트**: 후보 카드를 보고 순번에 따라 지명한다. 후보 풀과 지명 순번은 시즌 성적과 연동한다.
- 선수 카드의 희귀도와 성장 상한(POT)이 수집의 목표가 된다.
- 확률형 뽑기는 MVP에서 제외하고 선택형 획득으로 시작한다.

### 5.4 이적: 단장의 역할 (구현됨)

계약이 끝나는 시점이 단장의 가장 중요한 순간이다. 시즌이 끝나면 다음 순서로 진행된다.

```
노화·은퇴 → ① 트레이드 창 → ② 재계약 협상 → ③ FA 시장(5라운드) → ④ 드래프트 → ⑤ 로스터 확정
```

**① 트레이드 창** (`src/trade.mjs`)
- AI 구단들이 단장에게 제안을 보낸다. 특히 **계약이 끝나가는 선수**를 노린 제안이 온다. 재계약할 캡 여유가 없는 구단은 그 선수를 곧 떠날 선수로 보고(가치 낮게), 여유가 있는 구단은 가치 있게 본다. 이 차이에서 서로 이득이 되는 거래가 생긴다.
- 제안의 절반은 단장에게도 이득이 되는 거래, 나머지는 AI가 이득을 최대한 챙기려는 거래다. 단장은 수락·거절하고, 직접 거래를 제안할 수도 있다(AI가 가치를 평가해 수락·거절).
- AI 평가: 구단 성향(우승 도전은 즉전력, 리빌딩은 젊은 선수), 계약 만료 여부, 포지션 필요도를 반영한 가치의 합이 마진(5%) 이상이어야 받는다. 핵심 선수 3명은 웬만해서는 내놓지 않는다.
- 규칙(게임용 단순화): 외국 선수는 트레이드 불가. 오프시즌에는 거래 후 국내 선수 10~14명, 시즌 중에는 같은 인원끼리만 교환하고 36일차에 마감. 캡을 넘는 구단은 받는 연봉이 늘어나는 거래를 할 수 없다.

**② 재계약 협상** (`src/freeagency.mjs`)
- 선수는 `제안 연봉 ÷ 요구 연봉`, 구단 성적, 출전 기회, 원소속 구단 충성도, 숨은 기분을 합산한 점수로 수락 여부를 정한다. 요구액의 90% 미만은 항상 거절한다.
- 요구 연봉은 능력(OVR)에 가파르게 오르고(상한 8억), 어리고 잠재력이 크면 더 높으며, 노장은 낮다.
- 재계약하지 않거나 거절당한 선수는 FA 시장으로 간다.

**③ FA 시장**
- 5라운드. 매 라운드 AI 구단은 빈 자리·캡 여유·포지션 필요·가격·보상금을 따져 후보 3명에게 제안하고(우승 도전 구단은 5% 더 얹는다), 단장도 제안을 낸다. 선수는 가치가 높은 순서로 가장 좋은 제안을 고른다. 안 팔린 선수의 요구액은 라운드마다 4%씩 내려간다.
- AI 구단은 자기가 놓아준 선수를 다시 잡지 않는다.
- **FA 보상**(관리 규정 제6조): 다른 구단으로 이적하면 원소속 구단에 전년 보수 순위별 등급(A·B)의 보상을 낸다(4.2). 2027-28시즌 협상부터 A(1~30위)는 단장이 "보수 100% 현금" 또는 "보호선수 4명을 뺀 보상선수 + 보수 25%"를 고를 수 있고, B(31~40위)는 보수 50% 현금이다. 그 이전 규정(A 200% 또는 +50%, B 100%, C 41~50위 50%, 만 35세 이상 면제)도 `compensation.legacy`에 넣어 두었고 `effectiveFromYear`보다 이른 해에는 그 값을 쓴다. 게임의 오프시즌은 모두 2027년 이후라 항상 현재 규정이다.
- **FA 계약기간**(관리 규정 제4조): 전년도 보수 30위 이내 FA는 3~5년(만 32세 이상은 예외), 그 밖에는 5년 이하. AI 제안과 단장 제안 모두 이 범위로 맞춘다. FA 자격(계약 기간 중 매 시즌 정규시즌 절반 이상 출전), 자율협상 15일·영입의향서 3일·원소속구단 재협상 4일의 일정은 5라운드로 단순화해 아직 반영하지 않았다.
- 한 시즌 FA 계약은 15~20건, 그중 타 구단 이적은 평균 9건 안팎이다.

**④ 드래프트와 ⑤ 로스터 확정**은 5.9 참고.

**오프시즌 화면의 판단 도구** (구현됨): 재계약·FA·FA 보상·드래프트·외국인 영입·트레이드 제안·시즌 중 트레이드 화면의 선수 이름은 눌러지는 버튼이고, 누르면 "선수 정보 창"이 뜬다(능력치 여섯 줄을 같은 포지션 리그 평균과 비교, 계약, 이번 시즌 게임 기록, 있으면 KBL 공식 기록 최근 3시즌, 시즌 카드는 그 카드의 시즌·구단, FA는 원소속·요구 연봉). 외국인 영입 단계는 외국인 자리(찬 칸/빈 칸)와 외국 선수 연봉 사용액·이번 계약 최대 금액, 하위 팀부터 고르므로 우리 앞에서 이미 영입된 선수 목록을 보여 주고, 연봉 한도 때문에 못 고르는 후보는 지우지 않고 흐리게 두며 이유("요구 53만 달러 > 이번 계약 최대 50만 달러")를 적는다. 후보가 모두 한도에 걸리면 안내와 함께 가상 외국인 자동 영입 버튼이 나온다(ok가 아닌 후보를 고르면 엔진이 무시하고 자동으로 고른다). FA 각 라운드가 끝나면 우리 제안마다 결과(수락 / 다른 구단이 더 좋은 조건 / 요구액의 90% 미만 / 수락 점수 부족 / 캡 한도 / 로스터 자리 없음)를 기록해 다음 라운드와 드래프트 첫 화면에 "우리 제안의 결과"로 보여 준다. 기록은 표시용이고 시장 결과에는 영향이 없다.

**단장 콜백**: 엔진은 단장의 결정을 `policy` 콜백으로 받는다(`trade`, `proposals`, `resign`, `freeAgency`, `compensation`, `draft`). 콜백이 없으면 단장 구단도 AI와 같은 자동 규칙을 쓴다. `src/manager-bot.mjs`는 이 콜백을 단순한 규칙으로 채운 자동 단장이며, 화면 없이 흐름을 검증하는 데 쓴다. 화면을 붙이면 사람의 선택이 이 콜백을 대신한다.

**아직 없는 것**: AI 구단끼리의 트레이드, 시즌 중 트레이드 제안(규칙 검증은 있음), 현금 트레이드, 외국 선수 교체 시장, 아시아쿼터.

### 5.5 경기 시뮬레이션과 플레이오프 (구현됨)

**경기** (`src/game.mjs`, 순수 함수)
- 입력: 라인업(엔트리 12명: 스타팅 5 + 벤치 7), 리그 기준점, 시뮬레이션 설정, 난수 생성기. 같은 시드면 항상 같은 결과.
- 선수별 출전 시간(스타팅 30·30·28·28·26분, 벤치 17·15·11·8·4·2·1분, 합계 200분. 스타팅·벤치 각각 OVR이 높은 순서로 나눠 주므로 화면의 포지션 자리나 목록 순서는 출전 시간에 영향이 없다)으로 가중해 팀 공격력과 수비력을 구한다. 공격은 슛·패스·운동능력, 수비는 수비·리바운드·운동능력에서 나온다.
- 팀 기대 득점 = 기본 76점 + (내 공격력 − 리그 평균) × 배율 − (상대 수비력 − 리그 평균) × 배율 + 홈 보정(±0.75). 여기에 정규분포 편차(표준편차 9점)를 더한다.
- 동점이면 5분 연장을 반복한다. 득점은 출전 시간 × 공격 능력에 비례해 선수별로 나누고, 합계는 팀 득점과 정확히 일치한다. 리바운드·어시스트·스틸·블록은 각 능력치에 비례해 배분하고, 득점은 능력치에 맞는 성공률로 자유투·2점·3점 성공/시도로 나눈다(팀당 평균 득점 77, 리바운드 38, 어시스트 17, 3점 성공률 33%). 이 기록이 5.8의 능력치 산출 입력이 된다.

**정규리그** (`src/season.mjs`)
- 10개 구단이 서로 6번(홈 3·원정 3) = 54경기, 54일. 순위는 승수 → 득실차 → 다득점 순(실제 KBL 규정과 다른 단순화).

**플레이오프** (현재 대진은 6팀 진출 기준, 실제 KBL 방식을 단순화한 초기안)
- 6강(5전 3선승): 3위-6위, 4위-5위
- 4강(5전 3선승): 1위-(4·5위 승자), 2위-(3·6위 승자)
- 챔피언결정전(7전 4선승)
- 시리즈마다 시드가 높은 팀이 홈 어드밴티지를 가진다. 5전은 홈 2-2-1, 7전은 2-2-1-1-1 순서.

**AI 라인업**: 코스트 제한 안에서 `스타팅 OVR 합 + 벤치 OVR 합 × 0.45`가 가장 큰 12명을 고른다.

**밸런스 점검 결과** (`node tools/run-season.mjs --seasons 500`, 가상 선수 데이터 기준)
| 지표 | 결과 | 비고 |
|---|---|---|
| 최강팀 / 최약팀 정규리그 승률 | 약 68% / 30% | 격차는 `ratingScale`로 조정 |
| 경기당 두 팀 합산 득점 | 약 152점 | 팀당 76점 |
| 5점차 이내 경기 | 약 30% | |
| 연장 경기 | 약 3% | |

**알려진 쏠림**: 가상 데이터에서 서울 삼성과 고양 소노가 우승의 약 80%를 가져가고 창원 LG는 플레이오프에 거의 못 간다. 엔진 문제가 아니라 구단별 초기 전력 차이가 크기 때문이다. 선수 데이터를 실제 로스터로 바꾸거나 생성 규칙의 구단 전력 편차(`teamBase`)를 줄이면 완화된다. 플레이어가 약팀을 키우는 구조에서는 어느 정도의 격차가 오히려 육성의 목표가 된다.

### 5.6 경제 (구현됨)

- **국내 연봉 곡선**: `min(8억, 0.3 + 20 × ((OVR−45)/40)^3.5)`. OVR 65 약 2억, 70 약 3억, 75 약 4.5억, 77 이상 8억. 현재 팀 연봉 합계는 15~27억이고 평균은 캡(30억)의 약 80%다. (이전 단계에서는 연봉이 너무 낮아 샐러리캡이 거의 작동하지 않았다. 이번에 바로잡았다.)
- **소프트캡**: 캡 30억을 넘길 수 있지만 한도는 캡의 120%(36억)이고, 초과분의 30/40/50%를 기금으로 낸다. AI 구단은 정상 계약으로는 캡을 넘지 않고, 신인 계약·최저 연봉(0.4억 이하) 같은 면제 계약으로만 넘는다. 캡 초과 영입은 단장이 직접 결정할 때만 가능하다.
- **구단 자금**(`src/funds.mjs`): 시즌 수입 = 입장 수익(홈 경기 관중 × 객단가) + 플레이오프 입장 + 중계권 + 모기업 스폰서 + 굿즈·기타 + 플레이오프 상금(5.15). 지출 = 국내 연봉 + 외국 선수 연봉(1달러 = 1,400원) + 소프트캡 기금 + 육성 프로그램 비용. FA 보상금은 구단 사이를 오간다(합계는 변하지 않는다). 구단 평균 수입은 약 46억으로 이전 모델(36억 + 16억 × 승률)과 같은 수준이다.
- 외국 선수 캡(100만 달러, 1인 70만 달러)은 그대로다.

### 5.7 카드 코스트와 라인업 제한 (프야매 방식)

선수 카드마다 **능력치 기반 코스트**가 있고, 한 경기에 내보내는 라인업의 코스트 합계에 제한이 있다. 좋은 카드만 모으는 것으로는 이길 수 없고, "누구를 빼고 누구를 넣을지"가 핵심 선택이 된다.

| 항목 | 규칙 (초기값, `league-rules.json`) |
|---|---|
| 코스트 공식 | OVR 40 이하는 1, OVR 99는 20. 구간 사이는 `t^1.6` 곡선으로 가파르게 증가 (`calcCost` in `src/rating.mjs`) |
| 라인업 | 엔트리 12명: 스타팅 5 + 벤치 7 (KBL 경기 엔트리) |
| 코스트 제한 | 라인업 합계 75 이하 (10명 기준 65였던 것을 12명으로 늘리며 같은 빡빡함으로 다시 맞춤) |
| 외국 선수 | 스타팅에 동시에 2명까지 |

- 현재 가상 선수 데이터 기준: OVR 65 선수의 코스트는 약 6, OVR 76은 10. 코스트 무시 최강 12명의 합이 75를 넘는 강팀(예: 고양 소노 77)은 주전급을 일부 벤치에서 빼거나 값싼 선수를 섞어야 한다. 가장 값싼 10명의 합이 제한보다 낮아 모든 구단이 라인업을 만들 수 있다. (테스트로 확인)
- 제한값 75는 가상 데이터로 맞춘 **초기값**이다. 10명 기준 65일 때와 비교해, 코스트 무시 최강 편성의 평균 코스트 대비 제한 비율(1.04)과 제한에 걸리는 구단 수(2개), 제한 때문에 잃는 점수(평균 0.5)가 비슷하도록 정했다(`league-rules.json` lineup._note). 시즌 카드가 늘어 OVR 분포가 바뀌면 다시 맞춘다.
- 포지션 구성 제한(PG 1명 이상 등)은 MVP에서 두지 않는다.
- **라인업 화면**은 반코트 그림 위에 PG·SG·SF·PF·C 자리 다섯 곳과 벤치 7칸을 놓고, 선수를 칸에 넣는다(자리를 누르고 목록·다른 칸을 누르기, 마우스로 끌어 놓기, 키보드). 선수의 포지션이 자리와 다르면 "인접"(가까운 포지션)·"어색" 표시가 붙는다. **이 표시는 보기용이고 시뮬레이션에는 영향이 없다**: 득점·출전 시간은 선수 능력치와 OVR 순서로만 정해진다. 스타팅의 자리 순서는 편성과 함께 저장된다.
- AI 구단도 같은 제한 안에서 라인업을 짠다.

**시즌 카드 확장 (예정)**: 같은 선수라도 시즌마다 다른 카드가 되고, 카드마다 OVR과 코스트가 따로 정해진다. 과거 시즌 카드는 능력치가 고정이고 현재 시즌 카드만 육성한다. 성적을 능력치로 바꿀 때는 그 시즌 리그 안의 백분위로 환산해 시대 간 비교를 공정하게 한다.

### 5.8 능력치는 기록에서 나온다 (구현됨)

능력치는 임의로 정한 숫자가 아니라 **선수의 기록을 변환한 값**이다. 실제 선수 기록이든 시뮬레이션이 만든 기록이든 같은 변환을 쓴다.

**변환 방식** (`src/stats-rating.mjs`)
1. 선수별 시즌 합계(득점, 리바운드, 어시스트, 스틸, 블록, 야투·3점·자유투 성공/시도, 출전 시간)를 36분당 지표와 효율 지표(TS%, 3점%, 자유투%)로 바꾼다.
2. 지표마다 **그 시즌 리그 안의 순위(백분위)**를 정규분포 점수로 바꾼다. 절대 수치가 아니라 순위라서 득점이 많던 시대와 아닌 시대를 같은 기준으로 비교할 수 있다.
3. 능력치별로 지표를 섞는다: 슛(TS%·3점%·자유투%·득점), 패스(어시스트), 수비(스틸·블록), 리바운드. 운동능력과 체력은 기록으로 직접 재기 어려워 대용 지표를 쓴다.
4. 리그 평균 62, 편차 10으로 되돌린다.
5. 출전 시간이 적은 선수는 포지션 평균 쪽으로 당긴다(1,200분에서 100% 신뢰).

**검증**: 시뮬레이션 기록으로 변환해 원래 능력치와 비교하면 슛 0.92~0.98, 리바운드 0.95, 패스 0.90, 수비 0.73~0.80 상관이 나온다. 운동능력(0.6)과 체력(0.75)은 대용 지표라 낮다.

**실제 기록 넣기**: `data/stats/base.csv`(선수별 시즌 합계)와 `data/rosters/<구단id>.csv`(이름·포지션·나이)를 두고 `npm run generate`를 실행한다. 형식은 `data/stats/README.md` 참고. 기록은 사람이 KBL 공식 기록실 등에서 확인해 넣는다.

**시즌 중 갱신** (`updateSkillsFromSeason`)
- 9경기마다 지금까지의 기록으로 **슛·패스·수비·리바운드**를 갱신한다. 새 능력치 = 시즌 시작 능력치 + 반영률 × (기록 기반 능력치 − 시즌 시작 능력치).
- 반영률 = 25% × 신뢰도(출전 시간). 시즌 초반에는 거의 움직이지 않고, 한 시즌을 다 뛰면 최대 25%까지 반영된다.
- 같은 포지션 안에서의 상대적 활약만 반영한다(센터의 슛이 가드보다 구조적으로 낮은 것이 능력치를 끌고 가지 않게 포지션별 평균을 시즌 시작 수준에 맞춘다).
- 운동능력·체력은 시즌 중에는 변하지 않는다. 나이와 훈련으로만 변한다.
- POT는 올리지 않는다.
- 갱신된 능력치로 AI 구단이 라인업을 다시 짠다.

### 5.8.1 실제 선수 가져오기 (구현됨, 실데이터 적용)

두 가지 화면에서 옮긴 자료를 합친다. 자세한 파일과 절차는 `data/players/README.md`.

- **선수기록(xlsx)** → 능력치. 25-26은 정규리그+플레이오프 누적, 26-27은 진행 중 기록이다. 두 시즌을 합쳐 계산하고 올해만 있는 신인은 올해 기록만 쓴다. 같은 이름의 선수는 플레이 스타일이 가까운 쌍끼리 잇고, 시트와 등록 화면의 표기가 다른 이름은 `name-aliases.csv`로 맞춘다.
- **등록선수 화면** → 현재 소속, 등번호, 포지션(가드·포워드·센터), 국내/외국/아시아쿼터 구분, 드래프트 연도(나이 어림).
- **2025-26 소속**은 선수기록 화면의 팀 아이콘을 읽고 승·패 제약으로 검증했다. 현재 소속과 비교해 이적을 확인하고 동명이인을 가르는 데 쓴다.

흐름: `build:real`(풀·정정표) → `apply:real`(구단별 로스터·기록 CSV) → `generate`(players.json).

- 포지션은 등록 포지션을 기록으로 세분한다(가드→PG/SG, 포워드→SF/PF). 로스터는 국내 12·외국 2로 출전 시간 순으로 뽑고 다섯 포지션이 모두 있게 보충한다.
- **아시아쿼터**는 아직 별도 칸이 없어 국내 선수로 취급한다(`asiaQuota` 표시만 남김). 외국 선수 2명 제한과 코트 위 외국인 규정과는 별개다.
- 올해 기록이 없는 등록 선수와 드래프트 기록이 없는 외국 선수의 나이는 생성기가 채운다(실제 값이 아님). 연봉·계약은 능력치에서 만든다.
- 시즌 종료 처리는 포지션이 빈 구단이 생기면 겹치는 포지션의 선수 한 명의 포지션을 가까운 쪽으로 돌린다(실제 로스터는 포지션이 유연하다).

### 5.9 시즌 종료 처리 (구현됨)

정규리그와 플레이오프가 끝나면 `runOffseason`이 다음 순서로 진행한다.

1. **노화·성장**: 5.2의 표대로 모든 선수가 한 살 먹고 능력치가 바뀐다.
2. **은퇴**: 나이별 확률(30세 1.5% → 34세 10% → 36세 20% → 38세 40% → 40세 100%). 능력치가 낮은 선수일수록 확률이 오른다. 외국 선수는 37세 초과 시 퇴장.
3. **계약 만료·이적**: 트레이드 창 → 재계약 협상 → FA 시장 순서로 진행한다(5.4). 외국 선수는 50% 재계약, 나머지는 새 외국 선수로 교체.
4. **신인 드래프트**: 후보 24명(가상 신인 18명 + 과거 시즌 국내 선수 카드 6장, 5.14)으로 4라운드. 1라운드 순서는 순번 추첨(직전 시즌 순위가 낮을수록 공이 많다), 짝수 라운드는 거꾸로(뱀 순서), 3라운드부터는 지명을 포기하는 구단이 많다. 지명은 `잠재력×0.6 + OVR×0.4 + 포지션 필요도`로 정한다. 못 뽑힌 선수는 FA 풀로 간다. 신인 보수는 지명 순번 구간별(4.2), 계약은 1라운드 3년·2라운드 이하 2년.
5. **로스터 정리**: 국내 12명을 넘으면 가치가 낮은 선수를 방출, 모자라면 FA 풀에서 영입(포지션 균형 우선, 캡 안에서).
6. 결과 보고서(은퇴·성장·방출·영입·드래프트 명단)를 돌려준다. 화면의 "시즌 결산"에 쓴다.

**장기 안정성**(`node tools/run-league.mjs --years 60`): 평균 OVR이 62~64 사이에서 유지되고, 편차는 약 9.5에서 더 커지지 않으며, 80 이상 선수는 15명 안팎에서 안정된다. 평균 나이는 26세 안팎이다.

**강팀 유지 정도**(20년 × 6시드, 이적 시장 포함): 연속 시즌 승률 상관 0.44, 20년간 우승팀 평균 7.7개 구단, 최다 우승팀 점유 27%(우승 점유 HHI 0.17, 완전 균등 0.10), 타 구단 FA 이적 연 9건. 한두 팀의 독주 없이 어느 정도 연속성이 유지된다.

**아직 단순한 부분**
- 부상이 없다. 이전 게임에는 극심한 부상이 영구 능력치 하락으로 이어지는 규칙이 있었다. 도입 여부는 열린 질문이다.
- 신인 드래프트 후보는 전부 가상 선수다.

**드래프트 순번 추첨(구현됨)**: KBL 2024·2025 드래프트의 방식이다(`data/history/drafts/*.json`의 `lottery`). 직전 시즌 순위가 낮은 팀부터 공 40·40·40·40·14·14·6·6·0·0개(합 200)를 받고, 공이 있는 팀끼리 가중 추첨으로 1~8순위를 정한다. 공이 없는 상위 두 팀은 9·10순위(순위가 낮은 팀 먼저). 2022·2023은 32·32·32·32·24·24·10·10·3·1이었고 규칙 파일의 `draft.lottery.balls`만 바꾸면 된다. 라운드는 4라운드, 홀수 라운드는 추첨 순서, 짝수 라운드는 거꾸로. 실제 2024·2025는 3라운드에 5~8명, 4라운드에 1~2명만 지명했고 나머지는 "지명포기"였다. 게임에서는 AI가 라운드별 확률(`pickChance` 1·1·0.4·0.15)로 지명하고, 단장은 라운드마다 지명 또는 포기를 고른다. 연고지명·얼리 엔트리·지명권 트레이드는 아직 없다.

### 5.11 아시아쿼터 (구현됨)

- 구단당 0~1명(`rules.roster.asia`). 선수 `origin`은 `asia`이고 국적(`nationality`)을 가진다. 국내 선수 12명·외국 선수 2명과는 별도 칸이다.
- 국내 선수 취급: 코트 위 외국 선수 수에 들어가지 않고(라인업 제한 대상 아님), 국내 연봉 캡 계산에는 들어가지 않는다. 구단 지출(자금 정산)에는 들어간다.
- 트레이드할 수 없고(`transactions.asiaTradable`), FA 시장에도 나오지 않는다. 계약이 끝나면 확률적으로 재계약(`asiaQuota.renewProbability`)하거나 떠난다.
- 시즌 종료 처리에서 빈 구단은 확률적으로(`signProbability`) 새 선수를 영입한다(필리핀·일본·대만·말레이시아·태국·인도네시아·베트남 중 국적, 가드 위주). 은퇴 나이는 36세.
- 실제 데이터: 2026-27 현재 9개 구단이 아시아쿼터를 가지고 있고(KCC는 없음) 등록선수 화면의 구분(a)과 시즌 이벤트의 외국인 선수 표에서 가져온다.
- **가정(공식 값 아님)**: 연봉 1.0~2.0억 원, 계약 1~2년, 재계약 확률, 영입 확률, 영입 선수의 능력치 수준. 2026-27부터 교체 시기 제한이 없어진 점은 시즌 중 교체 기능을 만들 때 반영한다.
- 아직 없음: 외국인 선수 2명 동시 출전을 2·3쿼터로 제한하는 규정의 쿼터별 시뮬레이션(규칙 값은 있다).

### 5.12 구단 이력의 게임 연결 (구현됨)

실제 시즌 이력(1997~2025-26)에서 구단별 **전통 점수**(0~1)를 만들고, 시뮬레이션 시즌을 이어 붙여 계속 갱신한다(`src/legacy.mjs`, `league.legacy`).
- 점수 = 최근 5시즌 승률(40%) + 최근 5시즌 플레이오프 성적(30%) + 통산 우승(플레이오프 우승 1, 정규시즌 우승 0.5, 10 상한, 30%). 이력이 없으면 중립 0.5라 영향이 없다.
- 효과 1, **팬 기반**: 구단 기본 수입이 전통 점수에 따라 ±12.5%(`funds.prestigeSpread`) 변한다.
- 효과 2, **선수 선호**: FA·재계약 협상에서 명문 구단이 약간 유리하다(`freeAgency.prestigeWeight`).
- 20시즌 시뮬레이션 8개 시드로 확인한 결과, 전통 반영으로 최다 우승 구단의 우승 비율이 24%에서 29%로 올랐다(왕조가 생기기 쉬워지지만 실제 리그의 최다 우승 구단 비율과 비슷한 수준).
- 아직 없음: 시즌 카드(과거 시즌 성적 → 카드), 구단 인기 화면, 팀 이력 열람 화면.

### 5.13 뉴스와 커뮤니티 반응 (구현됨)

FM처럼 시즌의 사건이 기사와 팬 반응으로 남는다. 기사·댓글·매체(코트사이드, 하프라인 뉴스 같은 가상 이름)는 **모두 게임이 만든 가상 콘텐츠**이고 화면 위에 항상 그렇게 적는다.

- **파생 데이터**: 저장하지 않는다. 세션이 가진 일별 결과·박스스코어·순위·플레이오프·오프시즌 보고서와 시드에서 언제나 같은 기사를 다시 만든다(`src/news.mjs`, 순수 함수. 화면 쪽 입력 조립과 캐시는 `web/lib/news-view.js`). 오프시즌에서 바로 불러온 저장은 같은 시드로 시즌을 한 번 다시 돌려 일별 결과를 얻는다(약 50ms).
- **기사 종류(21종 이상)**: 개막 전 전망, 개막전, 경기 결과(승·패·접전·대승·대패), 3·5·7·10연승, 3·5·7·10연패, 그날의 최고 활약(30점대 득점, 트리플더블급), 선두 교체·1위 등극·6위권 진입·이탈, 플레이오프 진출 확정·탈락 확정(승수만으로 확정되는 순간), 9일마다 한 바퀴 결산·반환점·정규리그 종료, 플레이오프 라운드 결과·우승, 시즌 결산, 은퇴·성장·하락, 트레이드, 재계약·결렬, FA 영입·이적·보상, 드래프트, 소프트캡 기금, 구단 재정.
- **문장 규칙**: 숫자와 이름은 실제 상태에서 채우고, 문장은 그 숫자로 확인할 수 있는 말만 쓴다(경기 흐름 같은 데이터에 없는 사실은 쓰지 않는다). 종류마다 제목·본문 템플릿이 4개 이상이고, 시드와 사건 키로 고르며 최근에 쓴 문구는 피한다. 조사(은/는, 이/가, 으로/로 …)는 받침으로 고른다.
- **댓글**: 기사마다 0~3개. 우리 팀 팬·상대 팀 팬·중립이 섞이고 닉네임은 가상이다. 선수 이름은 기록을 칭찬하는 말에만 나오고, 부정적인 말은 팀·전술·운영에 대해서만 한다. 욕설·비하·사생활·정치·지역/성별 혐오는 템플릿에 없다(테스트가 금지어를 검사한다).
- **팬 심리**: 0~100 점수. 직전 시즌 결과로 시작해 경기·순위·이적 사건마다 오르내리고 매번 50쪽으로 조금씩 돌아온다. 분위기 이름은 환호(72+)·기대(58+)·불안(44+), 그 아래는 최근 5건이 내려가는 중이면 격앙, 아니면 체념. 같은 승리라도 분위기에 따라 안도·환호 같은 반응이 달라진다. 팬 심리는 표시용이며 아직 게임 규칙(수입·FA 선호)에 연결하지 않았다.
- **화면**: 뉴스 화면(최신순 피드, 전체·우리 팀·리그·이적·커뮤니티 탭, 더 보기, 기사를 펼치면 본문과 댓글)과 홈의 "최근 뉴스" 카드.

## 6. 화면 구성 (MVP)

**구현 현황** (`web/`, `npm run web` → http://localhost:8080/web/): 정적 웹앱, 빌드 없이 `src/`의 규칙을 브라우저에서 그대로 실행한다. 저장은 `localStorage`(시드와 시즌 번호로 난수가 정해져 저장 후 이어도 같은 결과).
- 있음: 구단 선택, 홈(전력 순위·연봉 캡·자금·전통 점수·순위 흐름·핵심 선수), 로스터(정렬·필터·다른 구단 보기), 선수 상세(카드·레이더·계약·실제 프로필·게임 내 시즌 기록), 라인업(자동 편성·코스트), 리그(시즌별 순위·플레이오프·개인 기록·수상), 구단 역사(1997~ 구단별 요약·순위 흐름·우승 기록, 게임에서 진행한 시즌이 이어진다), 시즌 결산(요약·우리 팀 경기·오프시즌 보고서), 시즌 진행 버튼.
- 아직 없음(순서대로): 직접 결정 화면(트레이드 제안함, 재계약·FA 협상, 드래프트, 훈련 지정), 직접 라인업 편성, 경기를 하루씩 진행, 박스스코어, 구단 인기 화면, 3D 선수 뷰어. 지금은 자동 단장(`src/manager-bot.mjs`)이 단장의 결정을 대신한다.
- 직접 결정 화면은 엔진의 `policy` 콜백을 쓴다. 콜백이 동기 함수라, 오프시즌을 한 단계씩 끊어 사람의 선택을 받고 같은 시드로 다시 이어 돌리는 방식(결정 기록 + 재실행)을 우선 검토한다.


1. **홈**: 구단 현황(자금, 순위, 다음 경기)
2. **로스터**: 선수 목록 표(OVR, 포지션, 연봉), 정렬·필터
3. **선수 상세**: 카드 + 3D 뷰어(프로토타입 재사용), 능력치, 계약, 성장 기록
4. **라인업·전술**: 스타팅 5인 편성, 전술 설정
5. **경기 결과**: 박스스코어와 요약
6. **드래프트·이적 시장**: FA 목록, 트레이드 제안, AI 구단 거래 내역
7. **리그**: 10개 구단 순위, 일정
8. **설정·저장**

### 5.14 시즌 카드: 과거 시즌의 선수가 나온다 (구현됨)
공식 기록(`data/stats/official`, 1997~2025-26)의 선수 시즌 하나가 카드 한 장이다. "98 서장훈", "99 서장훈"처럼 같은 선수도 시즌마다 다른 카드이고, 이름 앞 숫자는 시즌 시작 연도 두 자리다(출범 첫 시즌 1997은 1997-98과 겹쳐 "97초"). `npm run build:cards`가 `data/cards/domestic.json`(2232장)·`foreign.json`(713장)을 만든다(출전 300분 이상, 정규시즌, 구단을 옮긴 선수는 합산).
- **능력치**: 그 시즌 리그 안의 백분위로 만든다(5.8과 같은 방식이라 시대 간 비교가 공정하다). 포지션은 KBL 프로필의 가드·포워드·센터와 기록의 역할 추정으로 정한다. 나이는 생년월일이 있으면 그 시즌 시작 무렵의 나이, 없으면 27세다. 잠재력은 그 시즌 OVR이라 성장 여지가 없고, 나이가 들면 일반 노화를 받는다.
- **신인 드래프트**: 한 해 후보 24명 중 6장이 과거 시즌 국내 선수 카드(나이 28세 이하, 출전 600분 이상). OVR이 높은 카드일수록 드물게 나온다(`cards.weightMid`·`weightScale`).
- **외국인 영입**: 외국인 자리가 비면 과거 시즌 외국인 선수 카드 14장이 후보로 나오고, 하위 팀부터 고른다. 단장은 오프시즌의 "외국인 영입" 단계에서 직접 고른다(요구 연봉은 OVR에 비례해 25~70만 달러, 외국 선수 연봉 한도 안). 후보가 모자라거나 한도에 걸리면 이전처럼 가상 외국인을 만든다.
- **한 사람은 하나**: 이미 리그에 있는 선수(kblId)와 먼저 나온 선수는 다른 시즌 카드로도 나오지 않는다. 같은 추첨 안에서도 한 사람의 카드는 한 장뿐이다.
- **시작 로스터**는 모두 2026-27 카드("26 허웅")다. 기사 문장에서는 연도 표기를 뗀다.
- 모든 확률·개수는 `league-rules.json`의 `cards`(게임용 값)에 있다.

### 5.15 경기장·관중·수입 (구현됨, 관중은 공식 집계에 맞춘 추정)
- **자료**: `data/history/attendance.csv`(1997~2026-27 시즌별 총 관중, 정규리그/플레이오프 구분 없음 — 2022-23·2023-24는 기사 값보다 커서 플레이오프 포함 합계로 보인다(추정)), `data/history/attendance-2023-24.json`(한스경제 기사: 2023-24 정규리그 총 738,420명, 입장 수입 약 100억 원, 서울 SK 114,229명(평균 4,231, 입장 수입 약 15.3억)·창원 LG 평균 3,572·부산 KCC 3,359·원주 DB 총 85,634명). 리그 평균 2,735명, 객단가 약 13,540원(SK 약 13,400원)이 이 자료에서 나온다.
- **관중 모델**: 경기당 관중 = 리그 평균(시작 시즌 2,987명 = 2025-26 총 913,983명 × 0.88(2023-24 정규/전체 비율, 추정) / 270경기) × 리그 규모 지수 × 구단 인기 × 상대·요일 변동. 구단 인기 = 구단 팬 기반 × (1 + 0.4 × (올해 승률 − 0.5)). 팬 기반의 출발값은 2023-24 구단 평균 관중 / 리그 평균(SK 1.55, LG 1.31, KCC 1.23, DB 1.16)이고 자료에 없는 여섯 구단은 남은 관중을 균등 배분한 0.794다. 해마다 승률·플레이오프 성적으로 ±하고(우승 +7%, 하위 −2% 등) 출발값 쪽으로 서서히 돌아온다(0.6~1.6배 안). 팬 기반은 `league.att`에 저장되고 이전 저장은 출발값에서 시작한다.
- **물가·성장(게임용 값)**: 리그 전체 관중은 연 1.5%(`revenue.attendanceTrend`)의 완만한 상승 위에 평균회귀와 작은 변동(과거 표에서 코로나·진행 중 시즌을 뺀 연간 변동의 표준편차 약 9%)을 얹고 시작 시즌의 1.8배를 넘지 않는다. 객단가·중계권·모기업 스폰서·굿즈는 시즌 연도로 계산한 물가 지수(연 2.5%, 2026-27 = 1.0)를 곱한다. 30시즌 시뮬에서 총 관중은 평균 약 81만 → 132만(1.6배)이다. 지출 쪽 규칙 상수(소프트캡 30억, 최저 연봉 등)는 그대로라 장기 구단 자금은 늘어난다(30시즌 뒤 구단 자금 700~2,200억): 후속 과제로 캡 상승을 제안한다.
- **입장 수익**: 객단가 = 좌석 등급(일반 1~1.8만원 85%, 응원·고급 2~3.5만원 13%, 프리미엄 4~10만원 2%) × 유료 비율 0.8 ≈ 1.35만원(사용자 자료는 가격 범위뿐이라 평균이 자료의 객단가에 오도록 맞춘 값). 플레이오프는 관중·가격이 늘어난다(결승 관중 ×2, 가격 ×1.7).
- **그 밖의 수입**: 중계권(승률에 소폭 비례), 모기업 스폰서(전통 점수에 비례), 굿즈(인기·우승)는 자료가 없어 구단 평균 수입이 이전 모델과 비슷하도록 지은 값이다(`revenue._note`).
- **경기장**: `data/arenas.csv`(구단 id, 경기장 이름, 수용 인원, 출처, 비고). 이름은 `teams.json`의 `arena`와 같다. **수용 인원은 확인한 값이 없어 모두 빈 칸이다**(웹 검색에서도 구단별 수치를 찾지 못했고 기억으로 채우지 않았다). 채우면 관중 상한·매진·점유율이 자동으로 나온다. 빈 칸이면 "수용 인원 자료 없음"으로 표시하고 상한 없이 계산한다.
- **화면**: 홈의 "구단 · 경기장" 카드(경기장, 관중, 객단가, 입장 수익, 수입 구성 막대, 리그 총 관중 추이, 물가 반영 한 줄), 시즌 결산의 "재정 내역".
