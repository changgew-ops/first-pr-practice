# 게임 기획서 (초안 v0.1)

농구 구단 GM 시뮬레이션 + 카드 수집·육성. 웹 / 싱글 플레이.

> 상태: 초안. 아래 수치와 이름은 모두 **제안값(예시)** 이며 플레이 테스트로 조정한다.
> 이 문서는 사람과 AI 에이전트 모두의 기준 문서다. 규칙을 바꾸면 코드보다 먼저 이 문서를 고친다.

## 1. 한 줄 요약

신인 선수 카드를 모아 키우고, 라인업을 짜서 시즌을 치르며 구단을 성장시키는 싱글 플레이 웹 게임.

## 2. 설계 기둥

1. **육성이 중심, 수집이 동기**: 새 선수를 얻는 재미와 한 선수를 키우는 재미가 서로를 받쳐준다.
2. **직접 조작 경기 없음**: 라인업과 전술을 정하면 시뮬레이션이 결과를 계산한다. 선택의 결과가 숫자로 설명되어야 한다.
3. **작게 시작**: MVP는 선수 20명, 1시즌, 저장 기능까지만. 에셋과 기능은 그다음에 늘린다.

## 3. 코어 루프

```
선수 획득(드래프트/영입) → 훈련·육성 → 라인업 편성 → 경기 시뮬레이션
        ↑                                                      ↓
   다음 시즌 ← 계약·재정 정산 ← 시즌 보상·성장 ←←←←←←←←←←←←←←←←┘
```

한 번의 "턴" = 하루 일정(훈련 또는 경기). 한 시즌 = 정규 경기 N경기 + 시즌 종료 정산. (N은 MVP에서 20경기로 가정)

## 4. 핵심 시스템 (MVP)

### 4.1 선수

| 항목 | 설명 |
|---|---|
| 기본 정보 | 이름, 포지션(PG/SG/SF/PF/C), 나이, 등번호 |
| 능력치 | 슛, 패스, 수비, 리바운드, 운동능력, 체력 (각 0~99) |
| OVR | 포지션별 가중 평균으로 계산한 종합 점수 |
| POT | 성장 상한. 육성 한계를 정한다 |
| 희귀도 | 일반 / 레어 / 에이스 / 레전드 (카드 프레임·성장 상한과 연결) |
| 계약 | 연봉, 남은 계약 기간 |
| 상태 | 컨디션, 부상 여부 |

### 4.2 육성

- 훈련 슬롯에 선수를 배치하고 능력치를 선택하면 경기 일정 사이에 경험치가 쌓인다.
- 성장 속도는 나이와 POT에 따라 달라진다. 어릴수록 빠르고, 상한(POT)에 가까울수록 느려진다.
- 과훈련은 컨디션을 깎아 경기력에 영향을 준다.

### 4.3 수집

- 시즌 종료 시 **드래프트**: 신인 카드 후보 N명을 보고 선택한다(후보 풀은 시즌 성적과 연동).
- 시즌 중 **영입**: 재정 한도 내에서 자유계약 선수를 영입한다.
- 확률형 뽑기는 MVP에서 제외한다. 선택형 획득으로 시작하고 필요하면 나중에 검토한다.

### 4.4 경기 시뮬레이션

- 입력: 스타팅 5인 + 전술 설정(템포, 공격 성향, 수비 방식) + 선수 컨디션.
- 출력: 최종 점수, 선수별 기록(득점·리바운드·어시스트), 승패.
- 목표: 같은 입력이라도 무작위 요소 때문에 결과가 달라지되, 능력치 차이가 크면 승률이 확실히 오른다.
- 시뮬레이션 코드는 화면과 분리해 **순수 함수**로 만든다(테스트와 밸런스 검증이 쉬워진다).

### 4.5 경제

- 재화: 구단 자금 하나로 시작한다.
- 수입: 경기 승리 보상, 시즌 성적 보너스. 지출: 선수 연봉, 훈련 비용.
- 연봉 총액 한도(샐러리캡)를 두어 "좋은 선수만 모으기"를 막는다.

## 5. 화면 구성 (MVP)

1. **홈**: 구단 현황(자금, 순위, 다음 경기)
2. **로스터**: 선수 목록 표(OVR, 포지션, 연봉), 정렬·필터
3. **선수 상세**: 카드 + 3D 뷰어(프로토타입 재사용), 능력치, 계약, 성장 기록
4. **라인업·전술**: 스타팅 5인 편성, 전술 설정
5. **경기 결과**: 박스스코어와 요약
6. **드래프트/영입**
7. **설정·저장**

## 6. 데이터 구조 초안

선수 데이터는 코드와 분리된 JSON으로 관리해 밸런스 조정을 쉽게 한다.

```json
{
  "id": "p001",
  "name": "예시 선수",
  "position": "PG",
  "age": 19,
  "number": 7,
  "rarity": "rare",
  "stats": { "shooting": 62, "passing": 70, "defense": 55, "rebound": 40, "athletic": 66, "stamina": 68 },
  "potential": 84,
  "contract": { "salary": 120, "yearsLeft": 3 },
  "assets": { "portrait": "assets/p001.png", "model": null }
}
```

## 7. 기술 방향 (제안)

- **웹, 서버 없음**: 정적 사이트로 시작. 저장은 브라우저 로컬 저장소(`localStorage`).
- 게임 로직(시뮬레이션, 성장, 경제)은 UI와 분리된 순수 모듈로 작성하고 단위 테스트를 둔다.
- 3D 선수 뷰어는 three.js (이미 프로토타입 있음).
- 언어와 프레임워크는 개발 에이전트와 함께 결정한다(작은 규모라 단순한 구성을 우선).

## 8. 에셋 파이프라인

| 단계 | 도구 | 비고 |
|---|---|---|
| 선수 2D 카드 이미지 | Canva `generate-image` | 스타일 가이드(색, 시점, 선 굵기)를 프롬프트에 고정 |
| 배경 제거 | Canva `remove-background` | 투명 PNG로 저장 |
| 3D 모델 | Weave (Meshy/Tripo/Hunyuan) → `.glb` | 크레딧 소모가 크므로 **대표 선수·레전드 카드에만** 사용 |

MVP 원칙: 모든 선수는 2D 카드로 시작하고, 3D는 선택 기능으로 둔다.

## 9. AI 에이전트 운영 (초기 2~3역할)

| 역할 | 맡는 일 | 산출물 |
|---|---|---|
| 기획·밸런스 | 이 문서 관리, 능력치 공식, 경제 수치 검증 | 문서 변경, 밸런스 표 |
| 개발 | 기능 구현, 시뮬레이션 코드, 테스트 | 브랜치와 PR |
| 에셋 | 이미지·3D 생성, 파일 정리 | `assets/` 파일 |

운영 규칙(제안): 기능 단위로 브랜치와 PR을 만들고, 병합 전에 사람이 확인한다. 역할은 필요할 때만 늘린다.

## 10. 열린 질문

- 시즌 길이와 한 턴의 단위(하루 vs 주)
- 선수 성장 곡선(나이별 증가폭)의 구체적 수치
- 확률형 요소를 나중에 넣을지 여부
- 게임 이름과 아트 스타일(현재 캐릭터는 반실사 일러스트 풍)
- 별도 저장소로 분리할지 (현재는 연습용 `first-pr-practice` 저장소에 임시로 둠)
