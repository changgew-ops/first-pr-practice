# 통합 검수(QA) 기록

기능 하나하나가 아니라 **"내가 바꾼 선택이 화면과 경기 결과에 일관되게 반영되는가, 저장했다 불러와도 같은 시즌이 이어지는가"**를 확인한 기록이다.
외부 리뷰어(코드만 읽고 실행은 안 함)가 짚은 항목 중 1단계(표시 전력·관중 기록·저장 복원·코트 자리)를 재현해 보고, 맞는 것은 고치고 테스트로 남겼다.
테스트는 `tests/integration.test.mjs`(9개, 시드 고정, 약 26초)이고 `npm test`에 포함된다. 실행 방법: `node --test tests/integration.test.mjs`.

검수 방식: 살아 있는 세션 A와, 중간에 저장(`serialize`)했다 복원(`restore`)한 세션 B에 **같은 조작·같은 진행**을 시킨 뒤 상태 지문(순위·선수·재정·부상·컨디션·편성·박스스코어 전체·플레이오프·오프시즌 결정·업적·목표 등)이 한 글자도 다르지 않은지 비교한다.

## 1. 다음 경기 전력 표시

- **재현**: 시즌 중 홈·시즌·로스터 화면의 "전력"은 `web/lib/game.js teamPower`가 **로스터에서 자동으로 짠 편성**(`buildLineup`)의 스타팅 OVR 평균 70% + 벤치 30%로 계산했다. 직접 편성, 휴식 지정, 부상, 컨디션 때문에 엔진이 실제로 쓰는 12명(`buildTeams` → `buildLineupHealthy`/`substituteInjured`)과 달랐다. 예: 에이스를 쉬게 해도 다음 경기 카드의 우리 전력은 그대로였다.
- **수정**: 엔진이 다음 경기에 쓰는 편성을 단일 출처로 삼았다.
  - `src/season-run.mjs`: `run.lineupOf(teamId)`(정규리그는 `regular.teams`, 플레이오프는 `poTeams`).
  - `web/lib/session.js`: `lineupOf` / `teamPower` / `powerRanking`(시즌 중에는 엔진 편성, 오프시즌·시즌 시작 전 구단 고르기는 로스터 자동 편성).
  - `web/lib/game.js`: `powerOfLineup`(70/30 식 한 곳). 화면 `season.js`(다음 경기 카드, 라벨 "전력(출전 편성)"), `home.js`(전력 순위·리그 전력 표), `roster.js`(스타팅·벤치 표시)가 세션 값을 쓴다.
  - 라인업 화면의 "자동 편성"(`autoDraft`)도 쉬는 선수를 뺀다(엔진과 같다).
- **테스트**: 직접 편성(약한 12명) → 표시 편성이 그 12명, 다음 경기 박스스코어가 그 12명 안에서만 뛴다. 휴식 지정 → 표시 편성에서 빠지고 그 경기에 안 뛰고 하루 뒤 해제. 부상 → 표시 편성에서 빠지고 그 경기에 안 뛴다. 30일 동안 매일 "표시 편성 ⊇ 박스스코어 출전자, 스타팅 5명은 전원 출전".
- **미해결 → 해결(7절)**: 전력은 OVR 기반 표시 지표이고 감독·전술·컨디션 보정(`teamMods.edge`)은 들어 있지 않았다. 시즌 프리뷰(`src/preview.mjs`)의 확률도 같았다. → 유효 전력(`src/effective.mjs`)으로 통일.

## 2. 지난 경기 관중

- **재현**: 경기 줄·박스스코어·플레이오프 표의 관중을 조회할 때마다 **현재 순위표의 승률**로 다시 계산했다(`web/lib/season-view.js attendanceCalc`). 10일차에 본 3일차 경기가 3,183명이었는데 54일차에는 3,088명이었다. 구단 수입 정산은 상대 목록을 번갈아 돌리는 별도 계산이라 경기 줄 평균과 장부 평균도 조금 달랐다(3,535 vs 3,531).
- **수정**:
  - `src/funds.mjs gameAttendanceCalc`(경기 단위 계산기). `src/season-run.mjs`가 경기가 진행되는 순간 관중을 계산해 경기 결과에 `att`(정수 하나)로 저장한다. 정규리그는 경기 **직전** 순위표의 홈 팀 승률(경기 전이면 5할), 플레이오프는 정규리그 최종 승률.
  - 시즌 정산(`revenueOf`)은 저장한 홈 경기 합계(`attReg`)와 플레이오프 경기별 `att`를 그대로 쓴다 → **경기 줄 평균 = 홈 카드 평균(장부) = 정산 입장 수입의 근거**가 같은 값이다.
  - 화면은 `g.att`를 읽는다. 저장값이 없는 결과만 지금 순위로 다시 계산하고 "(추정)"을 붙인다.
  - 저장 파일에는 경기 결과를 저장하지 않으므로(시드·조작 기록으로 재생) 용량 영향이 없고, 복원하면 같은 값이 다시 나온다.
- **같은 시드의 기존 결과가 바뀌는 점(의도)**: 구단 수입 중 입장 수입·관중 합계가 조금 달라진다(경기 때 승률로 계산하고 실제 대진 상대를 쓰므로). 시드 3개에서 한 시즌 홈 평균은 3,531→3,534, 3,798→3,870, 3,558→3,563으로 사실상 같은 수준이고 30시즌 재정 시험(`tests/revenue.test.mjs`, `economy.test.mjs`)도 그대로 통과했다. 경기 점수·순위는 바뀌지 않는다(관중은 점수에 영향이 없다).
- **테스트**: 10경기 뒤와 시즌 끝 뒤 같은 경기의 관중이 같다, 복원해도 같다, 우리 홈 경기 평균 = 장부 `attendance.avg`, 플레이오프 평균도 같다. `web-season.test.mjs`는 추정 표시를 검사한다.

## 3. 코트 자리 저장

- **재현**: `draftFromSlots`는 빈 자리를 걸러 내므로 가운데 자리를 비우면 편집 중 상태에서 자리가 당겨진다(PG·SG·SF·PF·C → PG·SG·PF·C·빈칸). 그러나 **편성은 스타팅 5명·벤치 7명이 모두 차야 적용**(`validateLineup`)되므로 빈 자리가 있는 편성은 조작 기록에 남지 않는다. 적용된 편성은 자리 순서가 그대로 저장·복원된다(압축 슬롯 경유 포함).
- **결과**: 저장되는 상태는 문제 없음 → **문제 아님**. 시뮬레이션은 자리를 따지지 않으므로(출전 시간은 OVR 순) 경기 결과에도 영향이 없다.
- **작은 수정 2건**(`web/views/lineup.js`): ① 편집 상태 캐시를 시드·시즌만으로 구분해서, 같은 게임의 다른 저장을 불러와도 이전 판의 편집 중 편성이 남았다 → 세션 객체가 바뀌면 버린다. ② 자동 편성 비교가 쉬는 선수를 반영하지 않았다 → 엔진과 같게 뺀다.
- **테스트**: 적용한 자리 순서의 저장·복원 왕복, 빈 자리 편성 거절과 조작 기록 불변.

## 4. 저장·불러오기 복원 정확성

조작 기록(seed + actions) 재생 방식이라 "기록되지 않는 상태 변화"가 있으면 어긋난다. 시나리오를 만들어 비교했다.

| 시나리오 | 결과 |
|---|---|
| 같은 날 여러 번의 조작(편성·휴식·전술·훈련 집중·영입·방출·웨이버 양수·연장·트레이드·감독 교체·외국인/아쿼 교체)을 한 시즌 내내(시드 4개, 5곳에서 저장) | 통과 |
| 부상 대체(외국인 일시교체) 진행 중 저장 | 통과 |
| 휴식 지정 후 저장 | 통과 |
| 정규리그 마지막 날 전날·직후, 플레이오프 시작 직전·직후, 1라운드 뒤, 플레이오프 끝, 시즌 종료 직후, 오프시즌 결정 도중(트레이드·재계약·FA·보상·드래프트 단계), 다음 시즌 시작(2시즌) | 통과 |
| 오래된 시즌을 정리한 저장(`keepSeasonsDetail` 1, 2시즌 진행) — 목표·신뢰도·팬 열기·업적·도감까지 비교 | 통과 |
| 옛 모양 저장(관중 상태·스태프·도감·업적·`po` 없음, 선수 신규 필드 없음)을 압축 안 한 JSON과 압축 슬롯으로 열기 → 시즌 끝까지 → 오프시즌 → 다음 시즌 | 통과 |
| **플레이오프 중 라인업 변경** | **어긋남 → 수정함** |

- **발견한 버그(플레이오프 편성)**: 플레이오프 중 `setLineup`을 해도 ① 살아 있는 세션에서는 **플레이오프 경기에 전혀 반영되지 않았고**(`createPlayoffs`가 시작 때 팀 표를 고정) ② 저장했다 불러오면 그 조작이 **정규리그 끝**(플레이오프 시작 전)에 적용되어 결과가 달라졌다. 라인업 화면은 "다음 경기부터 이 편성으로 뜹니다"라고 안내하고 있었다.
- **수정**: `season-run.mjs`가 플레이오프가 매 시리즈 읽는 팀 표(`poTeams`)를 편성 변경 때마다 갱신한다(다음 라운드부터 반영). `session.js`는 플레이오프 중 조작에 `po`(치른 라운드 수)를 기록하고 복원할 때 그 라운드에 맞춰 적용한다. `po`가 없는 옛 저장은 예전처럼 정규리그 끝에 적용된다(옛 결과 유지).
- **테스트**: 약한 12명으로 바꾼 뒤 우리 팀 경기 결과가 바뀐다(편성이 실제로 쓰임), 저장·복원 상태가 같다, 플레이오프 끝까지 같다.
- **알아 둘 점**: 이 수정으로 "플레이오프 중에 라인업을 바꾸던" 기존 세션의 결과는 이전 버전과 달라진다(이전에는 효과가 없었다).

## 5. 연결 시나리오: 외국인 부상 → 일시교체 → 편성 변경 → 저장 → 복귀 → 종료

시드 33·34(·35)에서 확인: 외국인이 5경기 이상 다침 → 대체 선수 일시교체 → 라인업을 자동으로 되돌리고 선수 한 명 휴식 → 저장·불러오기 → 시즌 끝까지.

| 확인 | 결과 |
|---|---|
| 로스터: 원선수와 대체 선수가 함께 있다, 같은 선수를 또 일시교체할 수 없다 | 통과 |
| 일시교체는 "기타 사유 교체 횟수"를 쓰지 않는다 | 통과 |
| 저장 직후·9일마다·정규리그 끝 상태 동일 | 통과 |
| 복귀 기록과 대체 종료 기록이 같은 날, 종료 후 대체 선수가 명단에서 사라짐 | 통과 |
| 기록 귀속: 대체 선수는 합류~종료 사이에만, 원선수는 부상 중에 뛰지 않음 | 통과 |
| 재정: 보수 총액 = 시즌 끝 명단의 연봉 합 + 대체 선수가 뛴 기간 일할 보수(오차 0.06억 이내, 시드 4개에서 정확히 일치) | 통과 |
| 시즌이 끝나면 일시교체 선수는 떠난다, 교체 로그(뉴스 재료)가 남는다 | 통과 |

## 6. 플레이오프 한 경기씩 진행과 진행 중단 (리뷰어 2단계)

| 확인 | 결과 |
|---|---|
| 한 경기씩 끝까지 = 라운드 일괄(엔진 `createPlayoffs`, 시드 여러 개) 순위·시리즈·박스스코어·관중 동일 | 통과 |

| 경기 사이 라인업·전술·휴식 변경이 다음 경기부터 쓰이고 복원해도 같다 | 통과 |
| 플레이오프 컨디션: 시작 때 전원 회복, 라운드 사이 회복, `enabled:false`면 이전 결과와 같다 | 통과 |
| 중요 사건 중단(부상·로스터 부족·웨이버·경계선): 켠 때만 멈추고 끈 때·테스트 진행은 안 멈춘다, 복원 후 알림이 다시 생긴다 | 통과 |
| `po`만 있는 옛 저장 열기 → 플레이오프 끝까지 | 통과(`actions` 태그만 다르고 상태 지문은 같다) |
| 진행 중 시리즈 대진표(부분 결과)·시리즈 상세 관중(추정 표시 없음) | 통과 |
| 브라우저 스모크(Playwright): 시즌 화면 진행 중단 카드, 홈 알림 카드, 콘솔 오류 없음 | 통과 |

- **발견·수정**: 시리즈 상세가 경기 줄 `att`를 안 넘겨 "(추정)"으로 나옴 → `seriesGameRows`에 `att` 추가.
- **밸런스(컨디션 플레이오프 적용 영향)**: 켜기 전후 시리즈 이변 비율 0.397 → 0.421, 정규리그 1위 시드 우승 비율 38% → 42%(표본 잡음 범위). 피로는 임계(70) 아래에서만 효과가 있어 `intensity` 1.3을 두었다.
- **남은 문제**: 트레이드 제안 도착 중단은 미구현. 감독·계약 만료 임박은 너무 잦아 제외. 컨디션·전술 효과를 프리뷰·전력 표시와 같은 계산으로 합치는 일(3단계)은 아직이다.

## 7. 유효 전력: 프리뷰·전술 적합도·컨디션·라인업·엔진이 같은 계산을 쓴다 (리뷰어 3단계·5-①)

- **문제**: 화면 전력은 기본 OVR(스타팅 70% + 벤치 30%)만, 경기 엔진은 거기에 감독·전술·컨디션 보정(`team.mods.edge`)을 더해 경기를 치렀다. 프리뷰 확률도 기본 전력만 입력으로 썼다. 전술 행의 "기대 득점 +N점"은 화면이 같은 식을 따로 한 번 더 계산했다(적합도를 소수 둘째 자리로 반올림한 값으로).
- **수정**: 새 순수 모듈 `src/effective.mjs`가 단일 출처다.
  - `computeTeamMods(teams, ctx)`: 엔진의 `attachMods`를 그대로 옮겼다(리그 평균 기준 전술 적합도·컨디션 평균을 위해 전 구단을 한 번에 계산). 엔진(`season-run.mjs attachMods`)이 이 함수를 부른다.
  - `effectiveOf(lineup, mods, rules)`: `{ baseOvr, edge, parts: { coach, tactic, cond }, tactic, fit, effective, pointsPerPower }`. `effective = baseOvr + edge ÷ pointsPerPower`.
  - `pointsPerPower = rules.effective.qPerPower(1.83) × simulation.ratingScale` ≈ 1.56. 전력 1이 경기 득점 차이로 몇 점인지. 1.83은 구단 편성 80개(시드 1개, 8시즌×10구단)에서 (공격+수비) 점수를 전력으로 회귀한 기울기(게임용 보정값, 다시 재려면 `node tools/calib-effective.mjs`).
  - 엔진 API: `run.effectiveOf(teamId)`(지금 경기에 쓰는 편성·보정을 읽기), `run.effectiveIf(teamId, 편성)`(편집 중 편성 미리보기: 다른 구단은 엔진 편성 그대로 두고 이 구단만 바꿔 같은 함수로 재계산).
  - 화면: `session.teamPower/powerRanking`(시즌 중은 엔진 값, 아니면 `web/lib/game.js effectiveTable`: 자동 편성 + 중립 컨디션 + 추천 전술 + 그 구단 스태프). 반환의 `power`는 유효 전력(화면 기본 표시), `baseOvr`는 기본 OVR 전력, `edge`·`parts`는 경기 보정.
  - 전술 이득은 `src/tactics.mjs tacticEdge` 한 식(엔진·화면 공통, 적합도 원값으로 계산). `recommend(..., tacMult)`가 `edge`를 함께 준다.
  - 프리뷰(`session.preview`)의 확률·기자단·베스트5는 유효 전력을 입력으로 쓴다.
- **표기 규칙(화면 전체)**: ① 기본 OVR, ② 성장 변화는 OVR 옆 "(+N)"(시즌 사이 `ovrWas` 대비), ③ 이번 경기에만 적용되는 보정(감독·전술·컨디션)은 점선 칩 "경기 보정 +0.8점"(`web/lib/mods-view.js`)과 컨디션 막대로 따로 표시한다. 서로 같은 +N/화살표/색으로 섞이지 않는다. 라인업(팀 전력 카드·자동 편성 비교), 홈(전력 순위·리그 전력 표), 시즌(다음 경기·상대 확인·플레이오프 다음 경기), 전술 카드, 프리뷰가 이 체계를 쓴다. 포지션 적합도는 엔진에 없어 표기하지 않는다.
- **검증**
  - 같은 시드 3개(31·32·33)에서 리팩터링 전후 한 시즌(휴식·전술 변경 포함)과 플레이오프의 경기 점수·박스스코어·관중·순위·재정이 **비트 단위로 같다**(해시 비교).
  - `tests/integration.test.mjs`: "유효 전력: 임의의 날 5곳…"(엔진 보정 = effective 모듈, 표시 전력 = 기본 + 보정÷pointsPerPower), "휴식·전술·컨디션·감독…"(추천 ≥ 균형 ≥ 맞지 않는 전술, 휴식하면 기본·유효 전력 하락, 화면 전술 이득 = 엔진 이득, 편집 중 미리보기가 지금 편성과 같은 값), "시작 전 표와 프리뷰는 저장·복원해도 같다".
  - 프리뷰 보정(`tools/preview-calib.mjs`, 8시드×10시즌=80시즌, 시즌 시작 전력으로 프리뷰 확률을 만들고 그 해 결과와 비교):

    | 입력 | 1위 후보 우승 확률 평균 | 실제 우승 | 6강 예측 적중 | 우승팀에 준 확률 | 로그 손실 |
    |---|---|---|---|---|---|
    | 기본 전력(이전) | 33.1% | 41.3% | 78.1% | 22.1% | 1.770 |
    | 유효 전력(이후) | 36.9% | 40.0% | 79.6% | 23.8% | **1.716** |

    유효 전력이 모든 지표에서 같거나 낫다. 모형 온도(`preview.gameTemp` 0.3)는 그대로 둔다.
- **남은 것**: 컨디션 보정은 시즌 시작 전에는 전원 새것이라 0이고, 플레이오프 평균은 진출 구단끼리 비교한다(엔진과 같음). 포지션 적합도는 엔진에 없다.

**알려진 한계**: (1) AI 구단은 시즌 카드를 일부러 모으지 않아 시너지가 사실상 0이다(20시즌 200팀·시즌에서 0단계 100%). (2) 시너지 카드의 선수 이름 목록은 가장 큰 묶음의 선수들만 보이고 동수면 OVR 합이 큰 묶음이다. (3) 오프시즌 영입 미리보기의 시너지는 자동 편성 기준이다. (4) "우승 반지 원정대" 같은 칸은 카드에 우승 정보가 있어야 하므로 아직 칸이 없다(`rules.synergy.slots`에 추가하면 계산·화면은 그대로 쓴다).
