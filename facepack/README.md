# KBL 전체 선수 페이스팩 v2

기존 엑셀 선수 목록 **1,454명**을 기준으로 만든 전체 매핑팩입니다. 2026-10-28 수집.
이 목록 밖의 선수 ID도 고정 가상 얼굴로 대체합니다. KBL에 존재했던 모든 선수를 빠짐없이 검증한 명부라는 뜻은 아닙니다.

| 구분 | 수 |
|---|---:|
| 선수 ID | 1,454 |
| 공식 프로필에서 실제 사진 확보 | 1,275 |
| 가상 얼굴 대체 | 179 |
| 대체 중 이미지 응답 확보 실패 | 163 |
| 대체 중 기본 실루엣 이미지 | 16 |
| 실제 사진 중 얼굴 위치 추정 / 점검 대상 | 25 |
| 유니폼 몸통 | 10 |
| 재사용 가상 얼굴 | 16 |

## 먼저 실행하기

ZIP을 전부 압축 해제하고 `full-facepack/index.html`을 Chrome/Edge 등 브라우저로 엽니다.
폴더를 그대로 유지하세요. 사진팩은 인터넷과 API 키 없이 동작하도록 만들었습니다.
이름/선수 ID로 검색하고, 얼굴 카드 또는 유니폼 합성을 선택할 수 있습니다.
`사진 상태 → 가상 얼굴 대체`에서 누락 선수의 대체 결과를 확인할 수 있습니다.

## 클로드 코드에 전달하기

`full-facepack` 전체 폴더를 프로젝트에 제공하고 `CLAUDE_PROMPT.txt` 내용을 요청하세요.
실제 게임 연결 방법은 `CLAUDE_INTEGRATION.md`, 최소 실행 예제는 `integration-example.html`입니다.
기존 20명 테스트팩 v1과 API 차이가 있습니다. **v2의 render()는 async이므로 await가 필요합니다.**

## 파일

- `faces/`: 실제 사진 1,275장의 압축 WebP. 최대 160×240, 원본 종횡비 유지.
- `uniforms/`: 10개 구단의 몸통용 사진. 470×609.
- `generated/atlas.webp`: 가상 인물 16종.
- `offline/`: 로컬 HTML용 이미지 데이터 조각. 필요한 조각만 로드합니다.
- `data.js`, `manifest.json`: 전체 ID·사진 상태·얼굴 위치·대체 얼굴 매핑.
- `facepack.js`: 비동기 렌더러. 필요한 선수만 불러오며 최근 사진 64개와 몸통 합성 32개를 캐시합니다.
- `collection-report.csv`: 이름, ID, 수집 상태, 원본 URL, 얼굴 위치 검출 방식.
- `collection-summary.json`: 집계.

## 품질과 범위

전원 동일한 최신 시즌 사진이 아닙니다. 과거 촬영본, 배경이 있는 사진, 저해상도 사진이 포함됩니다.
사진 파일은 전부 디코딩 검증했고, 이름은 공식 선수 ID로 연결했습니다. 모든 인물의 얼굴과 합성 품질을 수동 검수한 것은 아닙니다.
얼굴 위치는 자동 분석입니다. 자동 검출이 안 된 실제 사진 25장은 추정 좌표와 점검 표시를 사용합니다.
자동 검출 성공 사진도 얼굴 위치·머리카락·배경·목 경계의 보정이 필요할 수 있습니다.
실루엣 16장은 실제 얼굴로 세지 않고 가상 얼굴로 대체했습니다.
사진을 확보하지 못했다는 것은 이번 공식 URL 수집에서 확보하지 못했다는 뜻이며 다른 곳에도 사진이 없다는 뜻은 아닙니다.

유니폼 몸통의 등번호·포즈·체형·문신은 제공 선수 원본입니다. 게임 번호 자동 변경은 없습니다.
가상 얼굴 16종을 재사용하므로 서로 다른 선수 얼굴이 겹칠 수 있습니다. 선수 ID와 faceKey를 저장하면 시즌·이적 후에도 유지됩니다.
게임 원본 코드를 받지 못했으므로 실제 게임에 연결된 완성본은 아닙니다.

## 출처

KBL 공식 프로필 `https://kbl.or.kr/files/kbl/players-photo/{playerNo}.png`.
선수별 URL은 CSV에 있습니다. 촬영 시점과 시즌은 확인되지 않았습니다.
사진과 구단 표장의 권리는 원 권리자에게 있습니다. 가상 얼굴은 AI로 만든 허구 인물입니다.
이번 배포팩에는 대용량 원본 PNG를 넣지 않았습니다.

## 게임(이 저장소)에 연결하는 법

게임은 `facepack/`을 **선택적으로** 읽는다. 폴더가 없거나 일부만 있어도 오류 없이 기존 조합형 아바타로 대신 보인다(`web/lib/faces.js`). 사진은 HTML에 넣지 않는다 — 게임을 갱신할 때는 HTML만 바꾸고 페이스팩은 그대로 쓴다.

### 내려받기용 ZIP (세 개로 나뉨, 각 10MB 이하)
`node tools/build-facepack-zips.mjs`가 `dist/`에 만든다.

| 파일 | 내용 | 언제 필요한가 |
|---|---|---|
| `facepack-공통.zip` | 코드·`data.js`·`manifest.json`·`generated/`·`uniforms/`·문서 | 항상 |
| `facepack-사진-웹용.zip` | `faces/`(WebP 사진 1,275장) | 웹·개발 서버로 열 때 |
| `facepack-사진-로컬용.zip` | `offline/`(데이터 조각) | HTML을 파일로 직접 열 때(`file://`) |

세 ZIP 모두 최상위 폴더가 `facepack/`이다. **공통 + (웹용 또는 로컬용)을 같은 위치에 풀면 `facepack/` 폴더 하나로 합쳐진다**(둘 다 풀어도 된다). 이 폴더를 게임 HTML과 같은 곳에 둔다.

```
게임 폴더/
├─ 프로농구-단장-게임.html
└─ facepack/          ← 공통 + 웹용/로컬용을 풀어 합친 폴더
   ├─ data.js, facepack.js, manifest.json, generated/, uniforms/ …
   ├─ faces/          (웹용)
   └─ offline/        (로컬용)
```

| 실행 방식 | 폴더 위치 |
|---|---|
| 개발 서버(`npm run web`) | 저장소 루트의 `facepack/`(`web/`의 한 단계 위). `globalThis.KBL_FACEPACK_BASE`로 바꿀 수 있다 |
| 단일 HTML을 파일로 열기 | HTML과 같은 폴더의 `facepack/`(로컬용 `offline/` 조각을 읽는다) |
| 웹에 올릴 때 | HTML과 `facepack/`을 같은 위치에 올리고(웹용 `faces/`), 페이지에서 `KBL_FACEPACK_BASE`를 지정 |

### 어디에 어떻게 쓰이는가
- **로스터·라인업·도감·선수 정보**: 사진이 있는 선수만 사진(작은 크기는 얼굴, 96px 이상은 소속팀 유니폼 합성 상반신). 화면에 보이는 것만 불러온다. **사진이 없는 선수는 기존 일러스트 그대로.**
- **우승 화면(단체 사진)**: 팩이 있으면 소속팀 유니폼 합성 상반신으로 바뀌고 로스터 전체(최대 12명, 세 줄)가 선다. 사진이 없는 선수는 가상 얼굴 16종 중 하나(고정 id의 해시)가 몸통에 붙고 카드에 "가상"이 표시된다. PNG 저장도 같은 그림.
- **게임 선수 ↔ 사진**: 게임 선수의 `kblId`(KBL playerNo)로만 연결한다(이름으로 짝짓지 않는다). 현재 게임 선수 149명은 전원 명부에 있고 사진도 있다. 가상 얼굴은 `kblId ?? id`의 해시라 이적·시즌 변경·저장 불러오기 뒤에도 같다(저장 형식은 바뀌지 않는다).
- **구단 매핑**: `web/lib/faces.js`의 `PACK_TEAM`(wonju-db→db, seoul-sk→sk, suwon-kt→kt, changwon-lg→lg, busan-kcc→kcc, goyang-sono→sono, seoul-samsung→samsung, ulsan-hyundai-mobis→mobis, daegu-kogas→gas, anyang-jungkwanjang→kgc).

### 한계
- 몸통(유니폼)의 **등번호·체형·문신은 구단별 원본 그대로**다. 화면은 번호를 덧붙이지 않는다. 목 연결이 어색한 선수가 있다.
- 사진 촬영 시즌은 확인되지 않아 최신 유니폼을 보증하지 않는다. 일부는 배경이 있거나 저해상도이고 25장은 얼굴 위치가 추정값이다.
- 가상 얼굴 16종은 서로 다른 선수끼리 겹칠 수 있다. 사진과 구단 표장의 권리는 원 권리자에게 있다.

## HTML 파일만 쓸 때 (웹서버 없이)

`dist/facepack.zip` 하나(공통 + 로컬용, 약 7.8MB)만 풀면 `facepack/` 폴더가 생깁니다. 이 폴더를 게임 HTML(`프로농구-단장-게임.html`) 옆에 두고 HTML을 더블클릭으로 열면 사진이 나옵니다. 폴더가 없으면 기본 아바타로 나옵니다. `facepack-사진-웹용.zip`은 웹서버에 올릴 때만 필요합니다.

### 사진이 안 나올 때
게임의 **홈 맨 아래 한 줄**이나 **저장 화면 아래 카드**에 이유가 한국어로 나온다.

| 문구 | 뜻과 할 일 |
|---|---|
| 페이스팩 폴더를 찾지 못했습니다 | 찾아본 위치 목록이 같이 나온다. `facepack` 폴더를 HTML과 같은 곳에 두세요 |
| 공통 파일은 찾았지만 사진 조각(offline/)이 없습니다 | 공통 ZIP만 풀었다. HTML을 파일로 열었다면 `facepack-사진-로컬용.zip`을 같은 `facepack` 폴더에 풀기 |
| 공통 파일은 찾았지만 사진(faces/)이 없습니다 | 웹으로 열었다면 `facepack-사진-웹용.zip`을 같은 폴더에 풀기 |
| 사진 사용 중 … 못 읽은 사진 N명 | 사진 파일 일부가 빠졌다. 사진 ZIP을 다시 풀기 |
| facepack 안에 또 facepack / ZIP 이름 폴더 안에서 찾았습니다 | 동작은 하지만 안쪽 `facepack` 폴더만 HTML 옆으로 옮기면 깔끔하다 |

게임은 `./facepack/`, `./facepack/facepack/`, `./facepack-공통/facepack/` 등 흔한 풀기 결과를 차례로 찾는다.

## HTML 안에 사진을 넣기 (폴더 없이 다른 PC에서도)

`tools/build-standalone.mjs`를 `facepack/`(data.js·facepack.js·faces/가 있는 폴더)가 있는 PC에서 돌리면, 사진을 줄여 게임 HTML 안에 넣습니다. 폴더 없이 HTML 하나만 복사해도 사진이 나옵니다.

```bash
ESBUILD=<esbuild 경로> node tools/build-standalone.mjs      # facepack/이 있으면 자동으로 내장
NO_FACEPACK_EMBED=1 node tools/build-standalone.mjs         # 내장 없이 3MB대 HTML
FACEPACK_PARAMS='{"photoScale":0.75,"photoQuality":45}' node tools/build-standalone.mjs   # 화질 조정
```

- 내장하는 것: 실사 1,275명(원본 160×240의 0.875배, WebP 품질 45, 평균 약 3KB), 유니폼 몸통 10장(0.5배), 가상 얼굴 16종(너비 640). base64를 포함해 HTML이 **약 8.9MB**(한도 10MB, 목표 9.3MB)입니다. 10MB를 넘으면 빌드가 실패합니다.
- 줄인 사진은 로스터·카드·도감·라인업 같은 작은 얼굴에 충분합니다. 선수 상세·우승 화면은 원본 크기로 합성하므로 **옆에 `facepack/` 폴더가 있으면 그 고해상도 사진을 우선 씁니다**(없어도 정상).
- 내장 사진은 필요한 선수만 이미지로 만들어 씁니다(처음 열 때 JSON을 한 번만 읽음).
- 결과 HTML(dist/)에는 실사 사진이 들어 있으므로 저장소에 올리지 않습니다.
