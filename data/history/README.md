# 팀 이력 (KBL 1997 ~ 2025-26)

KBL 공식 사이트의 "정규경기 → 시즌 선택" 화면(순위표와 플레이오프 대진표)을 화면 녹화로 읽어 옮긴 기록이다.
선수 기록과 달리 사람이 눈으로 읽어 옮긴 값이므로 **빌드 때 자동 검증**을 거친다(승패 합계, 승률, 순위 순서, 대진 정합성).

## 파일
| 경로 | 내용 |
|---|---|
| `raw/<시즌>.json` | 시즌별 원본 입력. 사이트에 표시된 구단 이름 그대로 |
| `franchises.json` | 구단 계보(현재 10개 구단과 이름·연고 변천). **빌드가 만든다** |
| `seasons.json` | 구단 id로 정리한 시즌별 순위·플레이오프. **빌드가 만든다** |

`npm run build:history`로 `raw/`에서 위 두 파일을 다시 만든다. 검증에 실패하면 어디가 틀렸는지 알려주고 멈춘다.

## raw 파일 형식
```json
{
  "season": "2025-26",
  "note": "(선택) 이 시즌에 대한 메모",
  "rows": [[순위, "구단 이름", 승, 패, 승률, "홈 승-패", "원정 승-패"], ...],
  "playoffs": {
    "seeds": {"구단": 시드},
    "r6": [["구단A", 승, "구단B", 승], ...],
    "r4": [...],
    "final": ["구단A", 승, "구단B", 승]
  }
}
```
플레이오프 화면이 없는 시즌은 `"playoffs": null`이고, 우승팀은 `"champion": "그 시즌의 구단 이름"`으로 적는다(나무위키 구단별 우승 연도 기준, 우승이 없는 2019-20은 `null`). 플레이오프 화면이 있으면 결승 승자와 같아야 한다. 빌드는 시즌마다 `championId`를 만든다.

`title-sponsors.json`은 시즌 범위별 타이틀 스폰서와 대회 명칭이다(예: 2011-12~2013-14 KB국민카드). 빌드가 모든 시즌에 `titleSponsor`로 펼치고, 빠진 시즌이 있으면 실패한다.

라운드별 순위와 MVP(선택, 지금은 2025-26만 있다)는 `rounds`에 라운드 순서대로 넣는다:
```json
"rounds": [
  {"rows": [[순위, "구단 이름", 누적 경기, 누적 승, 누적 패, 승률, 경기차, "라운드 승-패"], ...], "mvp": ["선수 이름", "구단 이름"]}
]
```
`mvp`는 없어도 된다. 라운드가 날짜로 나뉘어 팀마다 라운드 경기 수가 다르면(2023-24) `"uniformRounds": false`를 쓴다. 1라운드처럼 라운드 전적 열이 없으면 `null`을 넣는다. 빌드가 검증한다: 누적 경기 수, 승률, 경기차 계산, 라운드 전적 = 누적 변화, 순위(동률은 같은 순위이거나 최종 타이브레이크), 마지막 라운드 = 시즌 최종 순위.

팀 간 상대전적은 `"headToHead": {"teams": [구단 이름...], "matrix": [["-", "1:5", ...], ...]}`로 넣는다(행 구단의 승:패). 빌드가 대칭인지, 행 합계가 시즌 승패와 같은지 검증한다. 수상 기록은 `awards`(MVP·베스트5·수비상·신인상·감독상 등).

## 신인 드래프트 (`drafts/<연도>.json` → `drafts.json`)
지금은 2022~2025 드래프트가 있다(2023은 참가자 명단 없이 지명 결과만, `participantsKnown: false`)(해당 연도 11월에 열려 이듬 시즌에 합류: 2024 → 2024-25). 빌드(`npm run build:history`)가 검증하고 구단 id 기준의 `drafts.json`을 만든다.

- `lottery`: `[구단, 추첨 공(200개 중), 1라운드 추첨 순번]` 10개.
- `tradedPicks`: 지명권 트레이드. 그 라운드의 지명 구단만 바꾼다.
- `participants`: 최종 참가자 `[이름, 생년월일, 포지션(G/F/C), 키, 몸무게, 출신 학교, 자격구분]`. 생년월일은 선수의 실제 나이에 쓴다.
- `picks`: `{round, pick, team, name, school, position}` (+ 지명권을 넘겨받았으면 `originalTeam`). 지명을 포기한 순번은 적지 않는다.
- `territorialPicks`: 연고지명으로 드래프트 전에 합류한 선수.
- 검증: 추첨 순번과 공 합계, 라운드별 지명 순서(1라운드 = 추첨 순, 2라운드 = 역순, 3라운드 = 1라운드와 같음, 4라운드 = 역순), 지명 구단 = 순서상 소유 구단, 지명 선수가 참가자 명단에 있는지.
- 등록선수 화면(`data/players/registry.csv`)의 드래프트 연도와 교차 확인했다: 2024·2025 드래프트 지명자 중 현재 등록된 선수 46명(연고지명 2명 포함)이 모두 지명 목록에 있다.

## 새 시즌 추가하기
1. `raw/2026-27.json`을 같은 형식으로 만든다(시즌이 끝난 뒤).
2. 새로 나온 구단 이름이 있으면 `tools/build-history.mjs`의 `NAME_TO_FRANCHISE`에 추가한다.
3. `npm run build:history && npm test`.

## 알아둘 점
- **홈·원정 기록**은 사이트가 표시한 값 그대로다. 몇몇 시즌은 두 값의 합이 승패와 맞지 않는다(1997~2000-01은 경기 수 일부만 표시, 2024-25는 세 구단이 한 경기씩 어긋남). 빌드가 경고로만 표시한다.
- **플레이오프**는 2007-08부터만 화면에 있다. 그 이전과 2019-20(코로나로 조기 종료)은 없다. 우승팀을 모르는 시즌은 `null`이다.
- 일부 시즌은 화면 잔상으로 6강 대진이 가려져, 보이는 승수와 4강 진출팀으로 확정했다(`note`에 표시).
- 2002-03은 승·패 열이 가려져 승률과 홈·원정 기록의 합으로 승패를 확정했다(전 팀 일치).
- **구단 계보 연결**(예: 여수 코리아텐더 → 부산KTF → 수원 KT)은 데이터에서 이름 변천이 자연스럽게 이어지는 것으로 확인했고, 연고·인수 경위는 공식 연혁과 대조하지 않았다.
- 2026-27은 진행 중이라 제외했다.
