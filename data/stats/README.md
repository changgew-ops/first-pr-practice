# 실제 기록으로 능력치 만들기

`data/stats/base.csv` 를 두고 `npm run generate` 를 실행하면, 로스터 CSV(`data/rosters/<구단id>.csv`)에 있는
선수 중 이름이 같은 선수의 능력치를 이 기록으로 계산한다. 파일이 없으면 가상 능력치를 쓴다.

## 파일 형식
`_template.csv` 참고. 한 줄 = 선수 한 명의 시즌 합계 기록.

| 컬럼 | 뜻 |
|---|---|
| name | 선수 이름 (로스터 CSV와 똑같이) |
| games | 출전 경기 수 |
| minutes | 총 출전 시간(분) |
| pts, reb, ast, stl, blk | 득점, 리바운드, 어시스트, 스틸, 블록 합계 |
| fgm, fga | 야투 성공·시도 (2점+3점) |
| tpm, tpa | 3점 성공·시도 |
| ftm, fta | 자유투 성공·시도 |

- **KBL 사이트 "용어 설명"의 추가 항목**도 받는다: `oreb`(공격 리바운드), `dreb`(수비 리바운드), `to`(턴오버), `pf`(개인파울),
  `fbas`(속공), `gd`(굿디펜스), `dk`·`dka`(덩크 성공·시도), `pp`·`ppa`(페인트존 득점 성공·시도), `+/-`(득실마진), `sast`(스크린 어시스트),
  `dfl`(디플렉션). `reb` 대신 `oreb`와 `dreb`를 주면 합쳐서 리바운드로 쓴다. 이 항목들은 아직 능력치 계산에는 쓰지 않고 보관만 한다
  (턴오버는 패스, 굿디펜스·디플렉션은 수비 능력치 개선에 쓸 수 있다).
- 경기당 평균만 있으면 `평균 × 경기 수`로 합계를 만든다. 출전 시간은 `경기당 출전 시간 × 경기 수`.
- `#`으로 시작하는 줄은 무시된다.

- 추가 컬럼 `dd2`(더블더블), `td3`(트리플더블), `w`·`l`(그 선수가 뛴 경기에서의 팀 승·패)도 받는다. `w`·`l`은 팀 추정에 쓴다.
- KBL 기록실 xlsx는 `python3 tools/xlsx-to-stats-csv.py <xlsx> <시트이름> <출력.csv>`로 바꾼다. 출전 시간 셀은 `mm:ss`인데 엑셀이 `hh:mm`으로 읽어서 변환하고, 같은 이름은 `(1)`, `(2)`를 붙이며, 득점·리바운드·야투 합과 승+패=경기 수를 검증한다.
- 2025-26 시트는 플레이오프까지 합친 누적 기록이다.

## 능력치가 만들어지는 방식
1. 출전 시간이 300분 이상인 선수들로 리그 분포를 만든다.
2. 지표별로 리그 안의 순위(백분위)를 정규분포 점수로 바꾼다. 절대 수치가 아니라 **그 시즌 리그 안의 순위**다.
3. 능력치별로 지표를 섞는다.
   - 슛: 진짜 슈팅 효율(TS%), 3점 성공률, 자유투 성공률, 36분당 득점
   - 패스: 36분당 어시스트
   - 수비: 36분당 스틸·블록
   - 리바운드: 36분당 리바운드
   - 운동능력·체력: 기록으로 직접 재기 어려워 **대용 지표**(득점·리바운드·스틸·블록, 경기당 출전 시간)를 쓴다.
4. 리그 평균 62, 편차 10으로 되돌린다 (`league-rules.json`의 `ratingModel`).
5. 출전 시간이 1,200분보다 적으면 기록을 덜 믿고, 포지션 평균 쪽으로 당긴다.

시뮬레이션에서 나온 기록으로 같은 변환을 돌려 원래 능력치와 비교하면 슛 0.92~0.98, 리바운드 0.95,
패스 0.90, 수비 0.73~0.80의 상관이 나온다. 운동능력과 체력은 0.6~0.75 수준이다.

## 주의
- 실제 기록은 KBL 공식 기록실 등 공개 자료에서 직접 확인해 옮긴다. 에이전트가 추측해서 채우지 않는다.
- 이 폴더의 `_template.csv`는 형식 예시이며 실제 선수 기록이 아니다.

## KBL 공식 기록 (`official/<시즌>.csv`)
사용자가 준 xlsx(2026-10-23 조회, KBL 공식 기록 API 수집)를 `python3 -I tools/xlsx-to-kbl-official.py <xlsx>`로 바꾼 **1997~2026-27 전체 시즌** 기록이다. 위의 시즌 시트(`<시즌>.csv`)가 능력치 계산용 합계라면, 이쪽은 원자료다.
- 한 줄 = 선수번호·경기구분(`regular` 정규시즌, `playoff`, `final` 챔피언결정전)·소속팀. 시즌 중 이적한 선수는 팀마다 줄이 나뉜다. 출전시간은 초(`sec`). 성공률·평균은 계산할 수 있어 뺐다.
- 믿는 근거(테스트 `tests/official-stats.test.mjs`): 한 줄 안의 득점·리바운드·야투·승패가 맞고, 정규시즌 298개 구단 시즌마다 선수 출전시간 합이 200분×경기 수와 맞으며(0.98~1.03), 플레이오프는 이력의 시리즈 결과와 선수 승수·출전시간이 맞는다. 2021-22~2026-27은 위 시즌 시트와 모든 합계가 정확히 같다.
- 알려진 이상(테스트에 이유와 함께 적어 둠): 2008-09 플레이오프 강대협의 소속 표기(창원 LG ← 실제 기록은 인천 전자랜드), 2008-09 원주 동부 플레이오프 출전시간 합 부족.
- 선수번호(`playerNo`)로 `data/players/births.csv`(프로필)와 이어진다. 같은 사람이 번호 둘을 가진 경우가 있어(births.csv 비고) 사람 단위 집계는 이름+생년월일로 묶는다.
- 활용: 시트 이름 ↔ 선수번호는 `npm run build:ids`가 `data/players/season-ids.csv`로 만들고(동명이인 포함 1,112행 모두 한 명으로 정해짐), 화면용 시즌 기록은 `npm run build:careers`가 `data/players/careers.json`으로 묶는다. 옛 시즌(1997~2020-21) 소속과 선수 기록은 아이콘 판독 없이 여기서 바로 읽는다.
